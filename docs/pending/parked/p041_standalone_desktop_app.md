## 架构方向

- 后端保持 Python，不换语言。依据：cloakbrowser 官方封装库以 Python 为主（另有 JS、.NET）；PyInstaller 6.22.3 已支持 Python 3.15 并提供 macOS universal2 包；上游 CloakBrowser-Manager 曾以 Python 加 pywebview 打包桌面应用（v2 迁移时删除了 `app_entry.py`）。
- 在运行时层增加可替换接口：现有 Docker 运行时（Supervisor + Browser/Stream 容器 + Selkies）与新增的本机运行时（在宿主上直接启动和管理 CloakBrowser 进程）各实现一份。API、领域模型、数据库、前端、代理库、分组、自动化接口共用。
- 后端向前端上报运行能力（是否支持远程画面、可用的指纹平台），前端据此决定会话页是否存在，以及「打开」是进入会话页还是把本机浏览器窗口切到前台。
- 桌面框架候选：Tauri（Python 后端作为附带进程，自带签名与自动更新工具）、pywebview（纯 Python，最简单）、Electron（体积大）。立项时选定。
- 需要修订的 ADR：003（Chrome 标签页为唯一管理载体）、011（`--no-sandbox` 依赖容器边界；本机运行必须开启 Chromium 沙箱）。

## 强制全部流量走代理

分两层。浏览器参数层为默认且必做；系统强制层为可选项，启用后在「真实 IP 不泄露」上与 Docker 版等价。

1. 浏览器参数层（默认，必做）：只配置代理，不设绕过规则；`--force-webrtc-ip-handling-policy=disable_non_proxied_udp`（WebRTC 只经代理）；`--disable-quic`（关闭基于 UDP 的 HTTP/3）；HTTP 与 SOCKS5 代理下域名交给代理解析（待实测确认本机无 DNS 查询）；每次启动环境前自动做泄露检测，不通过则拒绝启动。此层依赖浏览器自身行为正确，浏览器缺陷或被攻破时不构成保证。
2. 系统强制层（可选）：应用内置 macOS 网络扩展（Network Extension，透明代理类型），拦截由应用启动的浏览器进程及其子进程的全部流量，按进程所属环境转发到该环境的代理；其余流量一律丢弃；代理不可用时断网，不回退直连。代价：网络扩展用 Swift 编写；通常需要付费 Apple 开发者账号以取得网络扩展权限并签名（届时核实）；首次安装需用户在系统设置中批准；Windows 需另行实现（基于系统对应接口）。用户当前没有付费 Apple 开发者账号，因此该层作为可选项：未启用时应用照常运行，并在界面上标明当前只有浏览器参数层的保护；取得账号后再实现与启用。
