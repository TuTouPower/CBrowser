# p122 代理使用环境计数含运行绑定但前端明细只认当前配置，计数与入口不一致

- 来源：2026-11-17 用户要求全面检查环境/代理数量增长下各处交互；审计代理“使用环境”计数与明细时发现，pending-record 分析登记。
- 现象：环境仍运行绑定代理A的旧配置，当前配置改为代理B后，A显示“1个使用环境”且删除被禁用，但该数量是普通不可点击 span，无法进入实际占用环境；多环境时明细也可能少于显示计数。
- 影响：代理列表与卡片使用环境入口、明细完整性和计数一致性；环境数量增加后更难辨认哪个运行实例仍占用代理。该问题与浮层滚动 p120 不同，少量数据也可复现。
- 根因：前后端引用口径不一致。后端 `ProfileRepository._proxy_used_by` 对当前配置引用与运行绑定版本引用取并集；前端 `ProxyListPage.tsx:141` 的 usedByProfiles 只按 list_profiles 当前 proxy_id 分组，未取运行绑定快照。`ProxyTable.tsx`/同页卡片用后端 used_by_count 展示数字，却按 usedByProfiles 数组长度决定静态/单项/多项导航。

## 复现与范围

1. 在 `.scratch/` 临时 SQLite 创建代理A、B及当前引用A的环境P，绑定P的版本1运行实例，再更新当前配置指向B。
2. 真实 repository 返回A used_by_count=1、当前 list_profiles 引用A数量=0；B count=1、当前引用B数量=1。A的运行绑定引用是合法占用，不能删掉计数或绕过删除保护来迎合前端。
3. 真实 ProxyTable 用 used_by_count=1、当前映射为空渲染，组件测试确认使用环境节点为 SPAN、文本含1、删除按钮 disabled。表格复现已运行；卡片有同一分支与同一数据来源，静态扫描确认同类，未声称卡片单独浏览器复测。
4. 并集混合态还可能显示“2个”但前端只拿到1个当前引用，走单项直达而漏掉运行绑定环境。此为同一分支推导，后续测试应实际覆盖；不把推导写成已运行场景。

## 期望与测试缺口

- 使用环境计数、明细与导航使用同一引用口径；覆盖当前引用、仅运行绑定引用、两者同环境去重、分属不同环境、停止解绑后释放等情况。
- 可解释当前配置与仍生效运行配置的占用差异，用户能够找到真正阻止删除的环境；保留后端删除保护，不将保护删除作为 UI 修复。
- 现有后端测试验证绑定引用删除保护，前端列表测试仅给当前配置映射与一致计数，缺少绑定旧版本后改代理的跨层测试，导致各层单独正确但组合入口失真。
- 补跨层数据来源回归及表格/卡片组件验证，断言显示数量等于完整可访问明细、1个可导航、多个有完整列表；结合 p120 验证大量关联环境仍可滚动到末项。
- 线索：`.scratch/repro_large_list_query_amplification.py` 的 bound_only_ui 输出；`.scratch/repro_collection_query_and_reference.test.tsx` 与 `.scratch/repro_collection_query_and_reference.vitest.config.ts`，2个组件复现全部通过。
- 查重：p104 已转交 t074，描述1个/多个使用环境交互目标，未记录运行绑定版本与当前配置引用口径不一致；新建缺陷，保留其历史不覆盖。
- 关联：p119 规模适配总表、p120 浮层滚动、p121 引用聚合查询效率；修性能与修展示都必须保留 union 语义。
