# p060 代理以分享链接为唯一录入入口并统一出口身份观测

- 来源：用户提出
- 内容：添加代理界面字段过多，用户只想输入「代理链接」和「备注」；粘贴链接后自动识别协议、地址、端口、账号密码，并通过 IP 回显自动判断出口国家。用户同时要求按「架构至上、拒绝妥协、零兼容性负担」重新审视根本原因，而不是折叠表单。
- 处理：未开
- 时间：2026-11-10T18:30:00+08:00
- 关联：p040（代理连通性与出口 IP 检测，已暂搁）、p038（内置 mihomo 代理节点，已暂搁）

## 用户原始诉求

添加代理弹窗当前暴露：名称、协议、地址、端口、用户名、密码、国家码、地区标签、备注，以及一个独立的「从 URL 粘贴」输入框。用户希望默认只看到：

1. 代理链接；
2. 备注。

粘贴后自动完成其余字段。国家不应由用户填写，而应通过代理访问 IP 信息网站，读取真实出口 IP 后判定国家。示例输入形态（凭证已脱敏）：

```text
http://127.0.0.1:7890
64.137.96.74:6641:<user>:<pass>
```

## 为什么不能按 UI 补丁处理

把 9 个字段折叠进「高级设置」只改变了可见性，没有改变系统模型。根本问题是当前实现把**存储 DTO 直接当作录入模型**：

- `ProxyCreateRequest` / `ProxyResponse` 以 `scheme`、`host`、`port`、`username`、`password` 五个平铺连接字段为真相；
- 表单再把它们逐一映射成输入框；
- `parseProxyUrl` 是表单顶部的辅助按钮，解析后仍写回平铺字段；
- 因此「链接」和「字段」成为两套可互相漂移的表示，任何高级字段修改都会让链接视图失真，反之亦然。

这违反单一真相源，属于把传输层结构泄漏为交互层结构。继续加折叠、开关、提示只会把错误边界藏得更深。

## 根本原因

### 1. 代理连接的领域模型缺少值对象

代理连接应是一个不可分的值对象，而不是五个可独立编辑的原始字段。链接是用户持有代理的天然序列化形态；平铺字段是存储/运行时展开形态。当前没有 `ProxyEndpoint`，导致解析逻辑只能停留在 UI 辅助函数层。

### 2. 国家被错误建模为静态配置

`country_code` 与 `name`、`notes` 同级，可由用户任意编辑。它实际是**出口 IP 的观测结果**，具有以下属性：

- 来源（自动探测 / 历史迁移 / 人工声明）；
- 观测时间；
- 观测视角（API、Browser Runtime、独立 broker）；
- 端点指纹与凭据版本；
- 有效期与失效条件；
- 可能为 unknown 或探测失败。

当前模型没有这些信息，端点或密码变更后国家不会失效，手动值可以和真实出口长期不一致，且无法判断某个国家值是否可信。

### 3. 探测视角与真实浏览器出口不一致

`docs/blueprint/supervisor.md` 明确：Browser 运行在独立 network namespace，网络策略默认拒绝私有与保留地址，代理只按解析后的地址和端口例外放行，端点 DNS 在 gated Runtime 内解析。p040 已记录同一结论：探测不能从 API 进程直接发起，否则结果与真实出口不一致且绕过隔离。

如果按「API 容器用 httpx 经代理访问 IP 网站」实现，得到的是 API 容器的网络路径，不是 Profile 中 Chromium 的网络路径。这会产生最危险的错误：界面显示国家正确，实际浏览器出口不同。

### 4. `127.0.0.1` 是视角相关地址，不是普通字符串

`127.0.0.1` 在宿主机、API 容器、Browser 容器中指向三个不同网络栈。当前把 `host` 当作无损字符串存储并直接交给 Chromium，用户输入本机代理时会出现「添加成功、启动后连不上」。这不是表单问题，是代理端点缺少「网络视角归一化」层。

正确方向二选一：

- 由统一 egress broker 为容器提供可达的代理端点；
- 或在 Supervisor 边界按消费方网络视角解析端点，并显式拒绝无法映射的 loopback。

不能靠 `host.docker.internal` 之类的局部替换长期糊住。

### 5. 链接录入会把密码带进 DOM 与前端状态

现有代理 API 刻意只写密码、不回显密码，`ProxyResponse` 只有 `has_password`。如果「代理链接」输入框保留完整分享链接，密码会进入：

- React state；
- DOM 输入框值；
- 浏览器表单历史 / 剪贴板扩展；
- 错误上报、调试快照或日志。

链接录入必须同时是 secret-safe 录入：解析后立即把密码移入只写槽位，展示层使用脱敏链接。

### 6. 探测接口存在已存凭据外送风险

若实现成 `POST /detect-country {proxy_id, host, port, username, password?}` 并在密码为空时复用代理库中的密码，调用者可以把已存密码连同任意 `host` 发给后端，形成 SSRF 加凭据外送。探测必须绑定代理身份与已存端点指纹；或只允许草稿使用显式临时凭据，绝不允许把已存秘密转发到请求指定的新端点。

### 7. 缺少草稿状态机

解析、字段校验、自动命名、国家探测、保存目前是分散的同步操作。需要显式的草稿状态：

```text
empty -> parsing -> parsed -> checking -> observed | unknown | failed -> saved
```

只有状态机才能统一处理并发探测、端点变更失效、重试、错误展示和「保存时探测仍未完成」的语义。

## 目标架构

### A. 领域值对象

新增 `ProxyEndpoint`：

- `scheme`、`host`、`port`、`username`；
- 密码只存 secret reference，不进入值对象序列化；
- 规范化不变量：scheme 白名单、IPv6 方括号、host 长度、端口范围、凭据归一；
- `fingerprint = hash(scheme, host, port, username)`，用于失效与探测绑定，绝不包含密码。

新增 `EgressObservation`：

- `proxy_id` 或草稿引用；
- `endpoint_fingerprint`；
- `credential_revision`；
- `observed_at`、`expires_at`；
- `vantage`：`browser_runtime` / `egress_broker`；
- `egress_ip`、`country_code`、`asn`（可选）；
- `source`：`probe` / `legacy_migration` / `declared`；
- `status`：`ok` / `unknown` / `failed`；
- `error_code`。

`country_code` 不再是 `Proxy` 的可写字段。UI 只展示观测状态；探测失败显示 unknown，并允许重试，不允许静默填写假值。

### B. 链接是唯一录入真相

`ProxyLinkParser` 下沉到领域边界，返回 `ProxyEndpoint` 或类型化错误。至少覆盖：

|格式|示例|说明|
|---|---|---|
|标准 URL|`socks5://user:pass@host:1080`|现有格式|
|无协议 host:port|`64.137.96.74:6641`|默认 http|
|host:port:user:pass|`64.137.96.74:6641:<user>:<pass>`|机场/住宅代理常见格式|
|user:pass@host:port|`<user>:<pass>@host:8080`|无协议但带认证|

解析成功后：

- 密码进入 write-only secret 槽位；
- UI 展示脱敏链接，例如 `socks5://user@host:1080`；
- 名称默认由 `host:port` 派生，用户可在高级设置覆盖；
- 高级字段从 `ProxyEndpoint` 反向渲染，不再独立维护第二份真相。

### C. 出口探测放在真实出口视角

探测由 Supervisor 执行，而不是 API：

1. API 发起 `POST /api/v1/proxies/{id}/egress-observations`；
2. 若代理未运行，Supervisor 创建一个短生命周期 helper，加入该 Profile 的 egress bridge / 等价网络视角，并安装与 Browser 相同的网络策略；
3. helper 使用与 Chromium 相同的代理启动参数访问最小 IP 回显端点；
4. 用本机 GeoIP 数据库把 egress IP 映射为国家，避免把出口 IP 送给第三方地理库；
5. 结果按 `(proxy_id, endpoint_fingerprint, credential_revision, vantage)` 写入观测，设置 TTL；
6. 端点或凭据变更、观测过期时自动失效。

草稿探测若必须保存前执行，使用独立 `POST /api/v1/proxies/egress-preview`：

- 只接受显式临时凭据；
- 禁止携带 `proxy_id` 复用已存密码；
- 限流、超时、网络策略与正常 Runtime 一致；
- 响应只含观测结果，不含凭据。

### D. 网络视角归一化

代理端点按消费方解析，而不是存一个字符串到处用：

- 长期方案：统一 egress broker 作为所有 Profile 的代理入口，用户链接由 broker 解析并转接到真实上游；Browser 只看见 broker 的容器内地址。该方向与 p038 有重叠，需要用户决定是否合并。
- 阶段性正确方案：Supervisor 在启动时按 Browser 网络视角解析端点；无法映射的 loopback 明确拒绝并给出可执行提示，不静默失败。

无论选哪条，都必须保证「探测视角 == 浏览器视角」。

### E. 前端交互

默认可见：

- 代理链接；
- 备注；
- 国家状态只读徽标（正在检测 / 已识别 US / 无法识别，可重试）。

高级设置折叠：

- 名称（默认 `host:port`，可覆盖）；
- 协议；
- 地址；
- 端口；
- 用户名；
- 密码（只写，永不回显）；
- 地区标签。

不允许在国家字段上随手填写。需要人工覆盖时必须产生显式 `declared` 观测并标记来源，不能伪装成探测结果。

### F. 破坏性迁移

执行「零兼容性负担」：

- 移除旧「从 URL 粘贴」按钮与独立粘贴框；
- 移除扁平连接字段表单模型，改由 `ProxyEndpoint` 驱动；
- 移除 `Proxy.country_code` 可写列，迁移到 `egress_observations`；
- 旧 `country_code` 以 `legacy_migration` 观测导入，状态标记 `unknown`，提示重新探测，不默认信任；
- 重新生成 OpenAPI 与前端类型；
- 不保留旧探测接口与旧字段兼容层。

迁移前备份数据库并验证可恢复；这是破坏性变更但不得丢失代理条目与 Profile 引用关系。

## 候选方案对比

|方案|结论|原因|
|---|---|---|
|只折叠 UI 字段|拒绝|不解决双真相源、国家语义与网络视角问题|
|前端直接请求 IP 网站|不可行|浏览器 fetch 无法指定代理；还会暴露凭据并受 CORS 限制|
|API 容器 httpx 经代理探测|仅可作临时验证|观测视角错误，且容易演变成 SSRF/凭据外送接口|
|Supervisor helper 在真实 egress 视角探测|采用|与 Browser 同路径，可复用网络策略与 GeoIP|
|统一 egress broker|待决策|能根治容器内 loopback 与端点分发问题，但与 p038 重叠且改动大|

## 验收标准草案

- AC-001：默认只显示链接与备注；高级设置默认折叠，展开后仍可编辑全部端点字段。
- AC-002：四类链接格式均可解析；非法输入显示字段级错误且不清空已解析结果。
- AC-003：解析后密码不在 DOM、前端查询缓存、URL、日志中出现；链接展示为脱敏形式。
- AC-004：名称在未手动修改时由 `host:port` 自动派生；手动修改后不被后续解析覆盖。
- AC-005：国家只读展示，来源与时间可追溯；探测失败显示 unknown 并可重试。
- AC-006：端点或凭据变更后旧观测立即失效，不允许沿用旧国家。
- AC-007：探测从 Browser 同网络视角执行；在「API 直连出口 ≠ 代理出口」的夹具下，观测值必须等于代理出口。
- AC-008：探测接口无法把已存密码发送到不同 host/port/scheme/username；有负向测试。
- AC-009：本机 loopback 代理要么通过 broker/视角映射可用，要么在保存或启动前显式拒绝并给出可执行提示。
- AC-010：端到端验证：粘贴链接创建代理 → 环境引用 → 启动 → 浏览器实际出口与观测国家一致。

## 测试缺口

- 链接解析矩阵缺少无协议、`host:port:user:pass`、IPv6 与特殊字符密码用例。
- 没有「已存密码不得外送到不同端点」的负向测试。
- 没有「API 网络视角 ≠ Browser 网络视角」的对照测试。
- 没有观测失效、TTL、凭据版本变更测试。
- 没有「密码不进入 DOM / query cache / 日志」的前端断言。
- 没有本机代理容器可达性端到端测试。
