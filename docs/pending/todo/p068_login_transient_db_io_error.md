# p068 登录页把可自愈的 SQLite I/O 故障暴露为不可重试 500

- 现象：2026-11-10 18:37:21–18:51:44（CST）期间点击「解锁」后登录页直接显示 `A database error occurred`；同一窗口 `/api/v1/auth/session` 也 500。18:56 再试即成功，API 容器全程未重启（`RestartCount=0`）。截图为该 500 的前端展示。
- 影响：登录与既有会话校验在数据库瞬时故障时完全不可用；前端只拿到英文原文，绕过 i18n。`cbrowser-api` 日志 966 行 `disk I/O error`、322 次 `Database error: OperationalError (disk I/O error)`，涉及 300 次 `profile_runtimes` 读、19 次 `sessions` 读、3 次 `sessions` 过期删除（登录建会话），说明密码校验已通过、失败发生在建会话写入。Supervisor/Gateway 同一时段正常，数据库副本 `PRAGMA integrity_check` 为 `ok`，恢复后无人为操作。
- 根因：应用层机制已验证。`src/backend/cbrowser/api/app.py:391` 的 `DBAPIError` 处理器把除 `IntegrityError` 外的异常一律映射为 500 `database_error` / `retryable=false`；`AuthService` 全部方法（`has_admin`、`authenticate_admin`、`create_session`、`get_valid_session`、`revoke_session`、automation token 系列）直接使用 `session_maker`，没有任何 `DBAPIError` 分类；`ProfileService._handle_db_error`（`src/backend/cbrowser/services/profile_service.py:334`）只把 `SQLITE_BUSY`/`SQLITE_LOCKED` 转成可重试 `DatabaseLockError`，`SQLITE_IOERR` 等同样落回通用 500。因此一次可自愈的 EIO 在对外契约上等价于永久故障。底层触发未复现：证据指向 SQLite WAL 位于 macOS 宿主 bind mount（`data/v2` → OrbStack 共享文件系统）时的瞬时 I/O/共享内存异常，而非代码写入错误（integrity_check 通过、自愈、仅 API 的 DB 句柄受影响）；已扫同类位点：`AuthService` 全部方法、`ControlService`（`session_maker` 直用无分类）、`NetworkService`、`ArtifactService/ArtifactRepository`；前端 `LoginPage.tsx` 仅透传 `err.message`，无错误码映射与重试。
- 测试缺口：现有 `test_a6_error_contract.py` 只断言 HTTPException 与 500 结构，`test_auth_service.py` 不注入 `OperationalError`；没有“认证/控制/网络接口遇 `SQLITE_IOERR` 应有确定降级或有限重试”的测试，也没有“登录失败错误码映射到 i18n 文案”的前端测试。应在 unit 层用可注入的 `OperationalError("disk I/O error")` 断言分类/重试边界，在 integration 层断言登录在建会话瞬时失败后可恢复，并补前端错误码到文案的断言。
- 线索：`.scratch/repro_login_disk_io_error.py` 以桩 AuthService 抛 `sqlalchemy.exc.OperationalError(..., sqlite3.OperationalError("disk I/O error"))`，复现返回 `500 {"error":"database_error","message":"A database error occurred","retryable":false}`。事故原始证据：`docker logs cbrowser-api -t`（`ERROR [cbrowser.api] Database error: OperationalError (disk I/O error)`，10:37:23Z–10:51:44Z），`docker logs cbrowser-supervisor -t` 同步记录 `api_status=500`。
