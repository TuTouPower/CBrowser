# p116 环境字体随系统自动配置，中文字体独立可选并核实 GPU 平台约束

- 来源：2026-11-17 用户口述及新建环境截图，`pending-record` 登记；新建与编辑均适用。
- 内容：系统平台决定对应字体，移除用户手选字体包的负担；语言与中文字体包含选项解耦；核实 GPU 指纹设置真实内核能力与平台组合。
- 处理：t075；resolution=transferred；reason=已核实根因、同类范围与验收契约，按用户授权聚合转交 t075（环境运行身份、字体资产与真实就绪契约统一）；转办不表示实现完成
- 关联：p118 承接表单布局、种子控件和高级选项说明；本条承接字体与 GPU 配置语义，不重复登记布局根因。

## 期望行为

1. 用户选择 Windows / macOS 后，系统自动使用对应平台字体，创建/编辑表单不再要求用户挑选“系统默认”或具体字体包，不展示 hash 供用户判断。字体资产管理与环境录入职责分离；所需字体缺失应提供明确可操作提示，不能悄悄使用不匹配平台字体。
2. 保留国家/地区对应语言选择，增加独立“包含中文字体”勾选项。至少支持英文环境自主选择包含或不包含中文字体，两种选择都要真实影响运行时字体暴露，而非仅改 UI。
3. 中文字体必须来自所选平台；平台切换、语言切换、保存后编辑回显、重启及克隆等现有配置生命周期应保持语义一致。新建默认值与既有环境如何迁移，实施规格明确，不在登记阶段猜定。
4. GPU 选项必须先核实当前固定版本 CloakBrowser 的实际支持、参数生效结果及各平台可用组合；说明它控制 GPU 指纹还是实际硬件。用户质疑 macOS 与 NVIDIA 组合，不得把无平台约束的通用选项直接提供给用户，也不能未经核实宣称所有 macOS/NVIDIA 历史组合均不可能。
5. 依据核实结果决定是否保留 GPU 手选、如何按平台自动选择或约束；若保留控件，应以用户可理解文案和说明解释作用，只提供有依据且实际生效的组合。当前未授权直接删除该功能。

## 规则变更与证据边界

- p069 / t053 历史规则要求英文环境不加载中文字体；本轮明确新增“英文也可勾选包含中文字体”，后续实施须同步更新生效契约、前后端配置、字体选择/挂载与验证，不能继续用 locale 单独决定是否含中文字体。旧条目已 closed，不回写历史验收。
- `ProfileForm.tsx` 当前保留字体集 Select（含“系统默认”与字体包，标签拼接 set_id 前八位），根据 locale/platform 选择默认值但允许手动覆盖。
- `profile_locale.ts` 当前 `selectFontSetForLocaleAndPlatform` 按 locale 选 core/CJK 包，不存在独立用户选择。
- GPU 当前领域字段仅 `auto/nvidia/intel`，前端选项无平台分流；`runtime_agent/runner.py` 将 nvidia/intel 转为 `--fingerprint-gpu-vendor=NVIDIA/Intel`。这仅证实项目参数传递，尚未验证内核是否真正支持或平台指纹是否一致。
- p074、p085 涉及更广身份一致性/群体分布且均已闭环；本条只承接本轮表单录入、字体策略和 GPU 平台有效性要求，不重开其全部范围。

## 验证方向

- UI：切换平台自动对齐字体且无手选包；英文下中文字体复选框可开关；保存重开正确回显。
- API/运行时：校验平台、语言、中文字体选择一致性；真实目标引擎探测开/关时中文字体暴露差异，避免前端勾选而 fontconfig/挂载未变。
- GPU：验证受支持组合的实际 WebGL vendor/renderer 及可用时 WebGPU 等可观察指纹，不以“参数已拼接”当作内核能力验收。新建与编辑共用约束，非法组合不能仅靠前端隐藏。
