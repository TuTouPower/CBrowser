## 4. 细项对齐与一致性审查

### 4.1 硬件配额与预算边界隔离（M1 Max 64GiB 宿主 vs 15.66GiB 容器）

- **核查项**：容器算力预算是否与宿主机物理资源混淆。
- **结论**：**符合要求**。
    - `v2_architecture_plan.md` §19.1 明确注明：“按实际配额测试，不把宿主64GiB全部计入容器预算”。
    - `t009`（依赖约束与 AC-001）明确约束：“Apple M1 Max/10核/64GiB Mac，OrbStack实际10 CPU/约15.66GiB”，不擅自扩大配额。

### 4.2 架构同源与指令集一致性（arm64 / aarch64）

- **核查项**：宿主机与容器是否属于同一指令集架构（同构运行，无 QEMU 仿真开销）。
- **结论**：**符合要求**。
    - 宿主 `arm64` 与 Docker `aarch64` 同属 64 位 ARM 指令集，为原生运行路径，规避跨架构模拟对基准的干扰。

### 4.3 媒体编码真实算力预算（OrbStack CPU 编码，不得虚报宿主 GPU 加速）

- **核查项**：容器内部媒体流编码是否违规假定宿主 Apple Silicon GPU 直通。
- **结论**：**符合要求**。
    - `v2_architecture_plan.md` §19.1 明确锁定：“Docker容器按CPU编码/无GPU加速基准；宿主Apple GPU不计入容器编码算力预算”。
    - `t009` 依赖约束中明确标注：“Linux aarch64、CPU编码”。

### 4.4 访问端与同机资源竞争（同机 Chrome 访问，共享 CPU/内存与后台负载）

- **核查项**：是否明确同机 Chrome 客户端与 Docker 服务共享资源，且禁止刷分行为。
- **结论**：**符合要求**。
    - 架构目标明确交付形态为：“通过同一台Mac的Google Chrome Stable访问使用”。
    - §19.1 明确指出：“CPU和内存在宿主Chrome与Docker间共享。不得为跑分擅自停止现有服务或扩大Docker配额。后续电脑/配额改变时重新记录环境，不能沿用旧结果”。

### 4.5 历史基准废止与豁免项标注规则（NOT_RUN / USER_WAIVED 而非 PASS）

- **核查项**：原远程 Linux x86（16 CPU / 32 GiB）是否已完全退出性能基准；公网/x86原生验证是否严格标注为用户豁免。
- **结论**：**符合要求**。
    - 方案修订段落明确：“用户明确指示‘把这两个跳过’：公网环境验证、原生 Linux x86_64 环境验证……记为 `NOT_RUN / USER_WAIVED`，不冒充通过，不再阻塞本次架构定案和后续实施”。
    - 强调“不能将本机数据当成被豁免环境的证明”。
    - `t009`（范围、AC-005、测试策略）与 `t012`（AC-002）均明确将公网穿透与原生 x86 实跑单列为 `NOT_RUN / USER_WAIVED`。

### 4.6 核心容量场景与验收硬指标保留

- **核查项**：核心容量场景（1/3/10流、10Profile 9静置1活跃）及稳定性/延迟/输入门禁是否完整保留。
- **结论**：**符合要求**。
    - **容量阶梯**：逐级测试 1、3、10 个活跃流，以及 10 个 Profile 同时运行（9 个后台流暂停、1 个前台流工作）。
    - **核心指标**：单活跃流 1080p30、同机 Chrome 端到端输入反馈 P95 ≤ 100ms、运行时就绪后首帧画面 P95 ≤ 1s。
    - **严苛测试保留**：8 小时连续媒体/生命周期压力测试（无数据损坏/串线/退出）、1000 次中文组合输入与 1000 次纯文本剪贴板验收，以及完整安全矩阵（计划 16 与 19.4）。均未因调整硬件基准而删除或减免。

### 4.7 真实容量认知（拒绝 10 流均达 30fps 的假定，拒绝虚假标称）

- **核查项**：是否避免不切实际的性能假设；资源不足时是否有明确的调度和报告机制。
- **结论**：**符合要求**。
    - §19.1 与 `t009` AC-001 明确表述：“10流场景用于找容量边界，不预设10路复杂网页都能1080p30。资源不足时必须明确报告，不能静默丢连接、OOM或损坏数据”。
    - 明确要求“CPU超过阈值或容器资源受限时按规则降低Profile级FPS，并明确显示资源限制”。

### 4.8 核心功能完整保留与交付目标收敛

- **核查项**：公网/TURN与跨架构能力代码是否保留；外部发布是否收敛。
- **结论**：**符合要求**。
    - 明确要求“保留公网/TURN配置、Linux x86_64镜像构建和相关功能实现；仅跳过上述环境上的验证，不删除功能”。
    - 交付范围明确收敛：“本次正式部署到当前电脑Docker，由本机Chrome访问；外部镜像推送/公网发布不在本次交付范围，另获明确目标授权后才执行”（`v2_architecture_plan.md` §目标、`t012` AC-004）。
