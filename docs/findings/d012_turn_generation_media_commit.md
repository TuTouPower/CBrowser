# d012 TURN 轮换须在新代接管和旧代退役后测媒体增量

- 来源：s008_turn_generation_media / t001

- 结论：make-before-break期间旧relay仍传媒体，不能以connected/relay/帧增长判断新代成功；真实commit、新ufrag selected pair和旧连接close+sendreject之后重新采样，才能证明新代媒体。

- 证据：初版独立无效第二轮新代0candidate却exit0假绿；代栅栏修订独立正常exit0/17.2秒、实际401/HTTP400负例exit1/15.6秒，旧媒体+39帧不再使新代通过。新代2/3接管后各+17/+15帧和非零音频能量/relay pair字节增长，见s008两轮独立报告。

- 影响：t004/t006必须保持真实ICE代切换判据；固定SDK私有适配器不是官方原生支持。主控后续移除临时凭证console并加PC/track引用检查，最终九源与独立R3快照逐字节一致；正常exit0/16.0秒、真实拒绝负例exit1/15.6秒，两轮引用===且各+16新帧；后续分离配置九源独立正常exit0/17.5秒、单侧失效矩阵exit1/33.3秒，本地宿主/内网不同URL和两端不同凭证均实际分配；公网/正式调度/原生Linux未验证，AC-004未通过。

- 现状：历史实验事实有效，已不适用于现行实现/验收（机制已由 ADR 013 删除；详见文末「后续（t024 文档收敛）」条）。

- 后续（t024 文档收敛）：本条所述 TURN/ICE 代次机制已由 ADR 013（同机直连，见 docs/blueprint/decisions.md）整体删除；本条仅作历史实验事实保留，不再构成现行实现或验收要求，文中指向未来 task 的指令已失效。
