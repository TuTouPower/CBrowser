# 038 统一 Profile 出站规划：SDK proxy= 集成、WebRTC/QUIC 加固与有代理净空 DROP 封闭（2026-11-15）

- 背景：s022（`docs/findings/d046_sdk_proxy_http_auth_and_geoip_routing.md`、`docs/findings/d047_chromium_webrtc_quic_leak_requires_netns_drop.md`）在真实 Docker 隔离网络命名空间内实测证实 ADR 037 原手写 `--proxy-server=` 方案存在四项系统性缺陷：(1) 手写 `--proxy-server=` 被迫触发 `proxy_http_auth_unsupported` 拒绝带认证 HTTP/HTTPS 上游，而改传 CloakBrowser SDK `proxy=` 可原生统一支持 `http://`、`https://`（含 TLS-to-proxy）与 `socks5://` 认证（特殊字符口令经 `urllib.parse.quote(s, safe="")` 编码）；(2) 手写 `--proxy-server=` 下 `geoip=True` 的外部 IP 探测会绕过代理直连并暴露宿主出口；(3) 原 Browser 与出口探测 helper 网络策略在丢弃私有网段后以 `-A OUTPUT -j ACCEPT` 结尾，导致 WebRTC STUN（UDP/3478）、外部 UDP DNS、QUIC/SOCKS5 UDP ASSOCIATE 与探测 helper 均可绕过代理直连公网；(4) 无统一单一出站规划源导致 `Runner`、`start_browser_container`、`browser_policy_spec` 与探测 helper 规则存在漂移风险。
- 裁决：
    - **单一权威出站规划**：在无状态中立包新增 `cbrowser/shared/egress_plan.py`（`ProfileEgressPlan`），作为运行期（`resolve_runtime_egress_plan`）、Supervisor 启动与巡检对账（`derive_supervisor_egress_plan`）及出口探测 helper（`probe_egress_plan`）的唯一出站规划权威；按纯配置与冻结快照判定 `proxy_enforced`，凭据文件缺失或损坏时失败封闭为 `proxy_enforced=True`。
    - **全量切换 CloakBrowser SDK `proxy=` 与零兼容移除**：删除手写 `--proxy-server=` 拼装、`ProxyHttpAuthUnsupportedError` 与 `proxy_http_auth_unsupported` 拒绝路径。`BrowserRunner` 统一把规范化代理 URL（含 IPv6 字面量括号与 URL 编码 userinfo）传入 `launch_persistent_context_async(proxy=...)`；有代理时统一注入引擎加固参数 `--disable-quic` 与 `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`。
    - **双栈强封闭网络策略**：在 `NetworkPolicySpec` 引入 `proxy_enforced: bool = False`。无代理直连模式保持 `proxy_enforced=False`（允许公网、仍拦截全部私有/保留网段）；一切有代理 Browser 容器与全部出口探测 helper 一律设 `proxy_enforced=True`，iptables 与 ip6tables `OUTPUT` 均以 `-A OUTPUT -j DROP` 终结（仅放行 loopback、ESTABLISHED/RELATED、解析后的上游代理 TCP 端口，以及当且仅当代理主机为域名而非 IP 字面量时的 `127.0.0.11:53/udp` Docker 内置 DNS），确保 WebRTC UDP/QUIC/外部 DNS/探测绕行在内核层面归零。`browser_policy_spec` 基于冻结 `snapshot.json` 与 `derive_supervisor_egress_plan` 对齐策略，任何规则退化由巡检触发 `fail_close_container`。
- 理由：将「认证代理支持 + GeoIP 同路出站 + 引擎级 QUIC/WebRTC 加固 + 内核级 netfilter fail-closed」统一在同一 `ProfileEgressPlan` 下，实现纵深防御并消除服务间契约分叉。
- 影响面：
    - `src/backend/cbrowser/shared/egress_plan.py`（新增统一规划），`src/backend/cbrowser/runtime_agent/runner.py`、`src/backend/cbrowser/supervisor/network_policy.py`、`src/backend/cbrowser/supervisor/docker_adapter.py`、`src/backend/cbrowser/shared/egress.py`（`probe_egress_plan` 同源策略）；
    - `docs/blueprint/{architecture,supervisor,security,testing}.md`、`docs/specs/{proxy_management,runtime_lifecycle}.md` 与 `docs/findings/d031_authenticated_socks5_supported.md` 同步修订（本决策在 `--proxy-server`、`proxy_http_auth_unsupported` 与有代理 `OUTPUT -j ACCEPT` 口径上替代 ADR 037）；
    - 本轮实证基于 macOS OrbStack Linux aarch64 容器（CloakBrowser `0.6.4` + Chromium `146.0.7680.177.3`）；`linux-x64`（`146.0.7680.177.5`）沿用既定环境豁免记为 `NOT_RUN / USER_WAIVED`。
- 复查条件：CloakBrowser 或 Chromium 主版本升级、或取消 `linux-x64` 豁免时，须重新执行 `s022` 同等双栈 netns 隔离与 WebRTC/QUIC/GeoIP 回归验证。
- 替代：继续保留 `--proxy-server=` 与仅对 socks5 开放认证（拒绝：HTTP/HTTPS 认证与 GeoIP 代理路由不可用）；仅依赖 Chrome CLI 旗标而不封闭 netfilter `OUTPUT -j DROP`（拒绝：`d047` 已证 UDP/STUN/QUIC 可从内核层逃逸）。
