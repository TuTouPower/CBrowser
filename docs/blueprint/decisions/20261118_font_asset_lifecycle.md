# ADR 030：字体集不可变资源生命周期（t081）

日期：2026-11-18。状态：已采纳，随 t081 实施。

## 背景

t041/t053 的字体集契约把「内容寻址不可变集」与「每次读取实时全量校验」
同时写进了不同组件：API 的每次 `get_font_runtime` 与字体列表都同步
`check_font_set`（143 文件、362 MB 逐文件 SHA-256），SSE 与绑定校验复用
同一重型 helper；API 测试固化「禁止缓存、宿主任意修改下一读立即可见」，
运行 Agent 却按 set_id 永久缓存同一结论。现场两次状态读取产生 286 次
哈希、724 MB 读取，60 秒采样 rchar 增长 34.6 GB。根因是不可变资产的
生命周期未定义：谁验证、何时验证、结论存哪、谁有权推翻，都没有契约。

## 决策

字体集是**发布后不可变的资源**，其生命周期只有四个阶段，验证结论只
由 API（唯一 DB 写者）持久化到资产目录 `font_set_assets`：

1. **发布**：受信发布者经 `scripts/import_font_set.py` 把来源目录的字体
    完整验证后以内容寻址 set_id 原子发布进 t080 的 fonts 卷（staging +
    rename 切换、同 ID 损坏集受控修复替换，均已由 t041/A19 实现，本 ADR
    不改变发布机制）。宿主字体目录自此只是显式导入来源，运行请求不再
    扫描它。
2. **接管（adoption）**：API 启动时枚举 fonts 卷上已发布的集（只读目录
    名，不读字体正文），对没有 verified 目录记录的集执行一次完整验证并
    写入目录记录（平台、来源/版本、文件数、总字节、detection 覆盖、验证
    状态/时间、资源修订）。发布与目录提交之间中断，恢复后只能得到「完
    整已发布资产 + 待接管」或「未发布」，不存在 ready 指向半成品；重复
    接管对已 verified 的集是无操作（不重验、不升修订）。
3. **显式审计（audit）**：`POST /api/v1/font-sets/{platform}/{set_id}/audit`
    或对未记录集的接管触发完整重验。审计在线程池执行（不占 API 事件
    循环），并发上限 `AUDIT_CONCURRENCY = 2`，同集在途请求去重（返回
    `in_flight`）。审计回执以调度时捕获的 `state_seq` 为围栏做条件写入：
    已应用的回执与接管都会推进 `state_seq`；发布/修复只写文件、不推进
    围栏，迟到的旧回执被丢弃，不覆盖已应用的新结论，修复经其后新的
    审计回执生效（失败方向封闭：旧回执至多让集暂时不可用，永不把损坏
    内容标为已验证）。审计失败把资源标记 `failed`：新绑定被拒、新启动被
    Supervisor 的实挂载校验拒绝；受控修复（重导入 + 审计）以新修订恢复
    `verified`。审计不删除、不重建任何浏览器用户数据。
4. **消费**：runtime REST/SSE、字体列表、默认集选择、Profile 绑定校验
    只读目录记录，复杂度与字体字节数无关（字体正文打开/哈希恒为零，
    由 test_t081 的计数门禁锁定）。运行状态报告的字体以**运行实例绑定
    的配置版本**为准（coordinator 按 `runtime.config_version` 取快照），
    待应用的新配置不冒充在跑实例的字体；无运行记录时报告当前配置
    （停止态）。Supervisor 对实际挂入的集做启动验证，每
    `(profile_id, runtime_instance_id, config_version, platform, set_id)`
    只验一次并缓存结论于该
    实例生命周期内；运行 Agent 的 `/health` 检测同理以其进程生命周期
    （= 实例生命周期）为围栏按 set_id 缓存。健康/状态读取永不重新哈希。

目录记录的 `revision` 在每次应用的目录变更（接管、审计回执、修复）
时递增，作为消费侧验证结论的围栏键；`state_seq` 只作审计回执围栏。

## 被替代的旧契约

- t053 A19「coordinator 每次实时读取、禁止缓存、删改下一读立即可见」
    与 A5「每次请求审计」语义整体废止；其测试
    `test_t053_coordinator_font_runtime.py`、`test_a5_font_scan_offload.py`
    整体删除（离线/有界这两条属性由 t081 测试在审计引擎上重新证明）。
    废止的直接后果是设计内的：已发布集在两次审计之间被外部篡改，不会
    被普通读取发现——这正是不可变资源的契约边界（卷对普通消费者只读，
    篡改只能来自越权写入），由显式审计负责发现，不再以每读全量哈希为
    代价换取即时可见。
- `list_font_sets` / `default_font_set` 的文件系统扫描实现保留为发布侧
    工具（导入 CLI 与部署预检使用），不再位于任何运行读路径上。

## 后果

- 状态读取成本与字体规模脱钩；现场 rchar 增长问题从根因消除。
- 默认集 = 目录中 verified 集按最近一次验证通过时间最新者（set_id
    字典序破平）：刚接管、刚审计或修复后重新验证的集胜出，与旧「最新
    导入的完整性通过集」口径同向。
- 基础完整性、detection 覆盖、真实渲染 ready 是三个不同状态：目录只记
    前两者，渲染 ready 继续由 t075 定义；`missing_fonts`（覆盖缺口）不
    作为完整性错误码。
