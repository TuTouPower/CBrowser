# Task spec

## 背景

Persona 创建期配置生成与引擎升级门禁是两个产品结果。本 task 从 t068/p085 分出，只有在数据、产品范围及实际引擎可控性确认后实施。

## 契约区

### 范围

- 基于有来源/版本且可合法使用的数据生成可复现 persona，使用 t068 探针与 t066 统一 seed/身份规则；只产生实际引擎支持的平台与字段。
- 跨字段自洽、种子碰撞/资源耗尽与统计分布可解释，不把“更多随机”当更隐蔽。

### 非范围

- 不实现预热/自检 UI；不增加未经支持的 Linux persona 或复活 parked p045；不声称组合永不复用/绝对不可聚类。

### 验收标准

### 有意不测

- 非范围中的新增产品功能不作为本 task 验收；已声明 AC 不豁免。

### 测试策略

- 固定数据/随机输入做可重复统计与非法组合、碰撞、耗尽测试；真实引擎核对生成参数，不依赖第三方反爬分数。
- 按 docs/blueprint/testing.md 的 doctor_cmd/test_cmd/blackbox_verify 执行；本次仅改 backlog，创建校验不代表实现验收。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- 是否实施自动工厂、数据来源/许可、平台范围和统计 N/阈值：UNVERIFIED-BLOCKING，用户确认具体方案后才能 start，不能只用同意方向替代数据和判定规则。
- 字段控制性：UNVERIFIED-SPIKE，消费 t068/实际引擎证据，不能按营销资料构造硬件组合。

### 风险与回退

- 风险：跨模块/制品或状态变更需按上述负向测试与 spike 验证；产品 BLOCKING 未消除不得实施。
- 回退：回退本 task 的完整实现 release；涉及数据先停写者并从已验证成套备份恢复，禁止仅降级数据库或以旧兼容分支兜底。

### 依赖与约束

- 硬依赖和冲突以 progress.md 的 task.py 调度字段为准；不把文件重叠当硬依赖。plan 仅输出图上候选，不能替代 preflight；产品 BLOCKING 必须先确认，SPIKE 先验证并回填。
