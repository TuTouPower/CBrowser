# p051 完整门禁 E2E 运行期容器消失（docker NotFound）定位与归属诊断

- 现象：t045 两次完整门禁（`CBROWSER_RUN_E2E=1 scripts/run_gates.sh`）各出现 1 个「容器在用例运行中途消失」失败，用例与标识均不同：首轮 `test_stream_selkies_tokens_e2e.py::test_e2e_ac010_gateway_topology_runtime_in_secure_mode_with_chrome` 在用例末尾扫容器日志时 `containers.get("t007-stream-tokens-gw-d64d93c1-browser-...")` 报 `docker.errors.NotFound`；第二轮 `test_runtime_coordinator_e2e.py::test_runtime_coordinator_docker_e2e`（serial，单进程阶段）`inspect_container("24a9a4d04f69...")` 报 404。两轮 AC-006 三个目标用例与 t019 均通过，但失败集合超出 t032 已登记基线。
- 影响：完整门禁 manifest `all_passed=false`；真实 Docker 拓扑用例在负载下持有旧容器引用即可能失败；E2E 失败集合超出 t019 基线。同类位点未穷尽（凡用例内跨较长时间持有容器名 / ID 的 E2E 都可能受影响）。
- 根因：**确切删除方未从现有日志确定，不得按「偶发竞态、重跑自愈」结案**。已逐一排除 t045 新增三条清理路径作为这两次失败的**直接**原因，证据：
    1. `scripts/gate_container_cleanup.py` 启动清理：唯一启动调用点在 `run_gates.sh` 的 `prepare_env` 之后、全部 suite 之前（E2E 容器尚未创建）；两轮主日志 `gate cleanup:` 仅出现 2 次（启动 + 退出），均为 `removed 0 containers, 0 networks`，E2E 运行期间无第三次调用。
    2. `EXIT` / `INT` / `TERM` trap 清理：主脚本退出才触发；实测 bash 后台子 shell（`backend_group &` / `frontend_group &`）不触发父脚本 `EXIT` trap；`gate cleanup:` 行数印证未在 E2E 中途执行。
    3. `SharedContainerStack.cleanup()`（前端 session E2E module 共享栈 teardown）：`test_frontend_session_e2e.py` 标 `serial`，在 `run_gate_suite` 串行 pytest 进程执行；首轮 ac010 在并行 pytest 进程（`-n 4 -m "not serial"`），两进程顺序执行、时间不重叠；共享栈 cleanup 走 `FrontendTopologyHarness.cleanup()` → `cleanup_prefixed_resources` 按 `com.cbrowser.prefix` label 精确匹配。
    4. `cleanup_prefixed_resources`（既有）：`gateway_probe/topology.py` 用 `filters={"label": f"com.cbrowser.prefix={prefix}"}` 加 `== prefix` 二次校验；ac010 的 prefix `t007-stream-tokens-gw-d64d93c1` 由 `secrets.token_hex(4)` 唯一生成，其它 worker 用例 prefix 各自随机，无法按 label 命中其容器。
        另：docker events 在首轮时间窗未保留（OrbStack 不持久化历史事件），首轮主日志已被第二轮覆盖，故无法直接读出删除方。**但已确认** `gate_container_cleanup.py` 原按名字前缀白名单匹配、不校验容器归属 label，若清理在 E2E 运行期间被调用会误删活动 worker 容器，属 t045 引入的确凿作用域缺陷，已加固。
- 测试缺口：原 `tests/unit/test_t045_gate_container_cleanup.py` 只覆盖名字前缀与生产容器保护，未覆盖「其它会话 / 活动 worker 容器」的归属判定；`cleanup_prefixed_resources` 删除容器时未记录调用方与 xdist worker，容器消失后无法归因。已补：① `gate_container_cleanup.py` 的 `select_cleanup_targets` 增加 `com.cbrowser.prefix` label 归属校验（名字命中但 label 属于其它会话不删），单测 `test_foreign_session_container_is_not_a_gate_leftover` / `test_gate_start_cleanup_never_targets_later_worker_containers`；② `cleanup_prefixed_resources` 增加删除诊断，按 `CBROWSER_E2E_DELETION_LOG`（由 `run_gates.sh` evidence 模式指向 `$EVIDENCE_DIR/container_deletions.jsonl`）逐条记录 `ts/action/container/label_prefix/cleanup_prefix/caller/worker`。
- 线索：首轮证据 `.scratch/t045_evidence_20261107_055516/logs/e2e.log`（ac010 traceback：用例 line 639 `containers.get`）；第二轮证据 `.scratch/t045_evidence_20261107_063228/logs/e2e.log`（runtime_coordinator traceback：`inspect_container` 404）。下轮门禁起读 `$EVIDENCE_DIR/container_deletions.jsonl`，按失败容器名 / ID 反查 `caller` 与 `label_prefix`；必要时订阅 `docker events`（destroy）并与诊断日志时间对齐。
- 第三轮门禁（`.scratch/t045_evidence_20261107_070309`）带诊断日志复核：`container_deletions.jsonl` 共 96 条删除，`label_prefix == cleanup_prefix` 全部一致（0 mismatch）、0 生产容器删除、19 个独立 prefix、worker 分布正常；`gate cleanup:` 仍仅启动 / 退出各 1 次且 `removed 0`。**未发现任何跨 worker / 跨会话误删证据，本轮未复现容器消失**。该轮 E2E 2 失败为 `test_control_handoff_e2e`（`Bind for 127.0.0.1:35001 failed: port is already allocated`）与 `t019` 首帧 3.36s（已登记基线），均非容器消失。端口冲突已由 t045 从根因修复：`GatewayTopologyHarness` 宿主端口改 OS 动态分配（`bind(0)` + 进程内唯一），脱离 `CBROWSER_E2E_HTTP_BASE` 固定段与 worker 争用；补 `tests/unit/test_t045_e2e_host_port_allocation.py` 防回归（未标 serial 的 E2E 不得固定宿主端口）。前两轮的容器消失（首轮 ac010、二轮 runtime_coordinator）无诊断日志，确切删除方仍未确定。
