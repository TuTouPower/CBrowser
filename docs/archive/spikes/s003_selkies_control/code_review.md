## 2. 原型可行性已证实的实质证据（本次执行观察）

1. **首次真实下载闭环（Line 274–321）**
    - 本地 HTTP 服务提供真实附件流（Line 20–29）。
    - 代理捕获到 `Browser.downloadWillBegin` 与 `Browser.downloadProgress (state: completed)` 事件（Log Line 22–28）。
    - 落地文件与 HTTP 原始内容比对一致（Line 320）。
2. **断开后自动触发恢复与第二次真实下载（Line 323–384）**
    - 外部客户端接入覆盖目录至 `external_downloads` 并关闭事件（Line 326–332）。
    - 客户端断开后，代理内部 `finally` 钩子自动向 Chrome 发送恢复命令（Line 181–183，Log Line 36–37）。
    - 二次下载落入默认目录且内容正确（Line 372–378）；`external_downloads` 断言为空（Line 383，Log Line 50–51），消除了覆盖残留假阳性。
3. **CDP 错误检查机制（Line 110–112）**
    - 恢复命令明确等待 Chrome 响应并校验 `"error" in resp`，避免静默失败。
4. **协同取消与超时设计（Line 163–168, 260–273, 406）**
    - 双向流采用 `FIRST_COMPLETED` 配合 `cancel()` 规避已知挂起路径（Line 163–168）。

5. **单次清理流程（Line 185–199, 392–401）**
    - 退出时显式取消 client 任务并关闭管理 WS；`finally` 终止 Chrome 进程及 HTTP 服务。
