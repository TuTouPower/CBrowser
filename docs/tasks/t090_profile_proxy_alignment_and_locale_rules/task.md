# Task spec

## 背景

重新打开已保存代理地域偏差的环境编辑表单时，`ProfileForm` 错误显示「已按代理 (JP) 默认对齐：Asia/Shanghai…」并隐藏「恢复默认对齐」按钮，且 CJK 摘要未读取实际 `include_cjk_fonts` 开关。同时，在已有代理默认时区时切换语言会反向把时区改回 `Asia/Shanghai`，且 `profile_locale.ts` 对代理名称采用子串匹配导致如 `"Tokyo Relay"` 命中 `"la"` 被误判为洛杉矶。

## 契约区

### 范围

- 修复 `ProfileForm`（覆盖创建、列表编辑弹窗及详情配置页共用表单）的代理对齐状态判定、摘要展示与「恢复默认对齐」入口，包括代理列表异步加载后的同步对比与重置恢复。
- 修复对齐摘要中 CJK 字体规则展示，确保始终按实际 `values.include_cjk_fonts` 开关渲染。
- 修复 `profile_locale.ts` 中 `timezoneForProxy` 的地域关键字词边界匹配，避免子串误判；消除在已有代理地域对齐或已有非空时区时修改 `locale` 反向改写 `timezone` 的错误联动（按用户确认保持仅支持 `zh-CN` / `en-US`，暂不新增 `ja-JP`）。

### 非范围

- 不扩展新增 `ja-JP` 等新语言枚举，不修改后端 `SUPPORTED_LOCALES` 与数据库 CHECK 约束。
- 不修改 GeoIP 优先级及跨地域运行链路。

- [x] AC-001：在编辑已有环境且所选代理存在可推断默认值时（含代理列表异步返回场景），只要保存的 `timezone` 或 `locale` 与代理推断默认值不一致，表单对齐摘要不得显示「已按代理默认对齐」，须明确提示偏离状态并显示「恢复默认对齐」按钮；点击恢复后将 `timezone`、`locale` 与 `include_cjk_fonts` 恢复为代理默认值且摘要回到对齐态；若时区与语言均与代理默认值匹配，则正常显示已按代理对齐且不误显重置提示。

- [x] AC-003：`timezoneForProxy` 按词边界匹配英文地区词项与缩写（如 `"Tokyo Relay"` 不再因含 `"la"` 命中洛杉矶，`"Germany"` 不再因含 `"ny"` 命中纽约，准确命中东京/德国默认时区）；且当已选代理存在推断时区或用户已设定/保留非空时区时，手动切换 `locale` 不再反向改写 `timezone`（未选代理且无时区的新建默认联动仍保持一致），全部前端单元测试、严格类型检查与构建通过。
