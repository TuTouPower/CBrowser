# Task spec

## 背景

字体路径在 Supervisor 与 Docker daemon 之间混用，四个现行 Browser 的字体源均指向错误的宿主 /fonts 子目录；隔离对照证实空目录使中英文文字像素为零，而真实平台字体集恢复正常。Supervisor 校验自己看到的资产，Runner 只校验 fontconfig XML 是否生成，Agent ready 不包含必需字形能力，三者没有证明消费同一份有效资产。

环境表单同时暴露字体包与无平台约束的 GPU vendor，并把 locale 当成是否包含中文字体的开关。配色又把 null 与 no-preference 同标为跟随系统。用户已批准按开发铁律统一运行配置语义、取消无依据的选项及降级路径；该 task 交付单一结果：每个可启动环境拥有固定、可解释、真正可渲染的运行身份。

## 契约区

### 范围

- 消费 t080/t081 统一的受管字体卷、资产目录与逻辑引用：Browser 目标路径固定，在集中配置及 volume_spec 边界构造精确只读挂载；移除深层临时读取环境变量、容器路径充当宿主源及旧宿主同路径挂载方案。资产不存在/不可用时拒绝，禁止隐式创建空源。资源发布/完整性审计由 t081 负责，本 task 负责产品身份、字形与真实渲染就绪。
- 将平台、语言、include_cjk_fonts 与固定字体集引用分离；中文默认包含中文字体，英文默认关闭但可显式开启。后端按经过验证的资产能力解析并版本化，取消表单手选字体包和靠名称/hash 猜 CJK 能力的规则。正式环境不再以 Linux 基础字体回退掩盖平台字体缺失。
- 以固定引擎、平台和持久 seed 驱动经过验证的 GPU 自动策略；取消无约束 auto/nvidia/intel 手选契约。先完成下方能力实验，再冻结平台能力矩阵；不能兑现的组合明确拒绝，不伪造支持。
- 网页配色偏好收敛为显式 light/dark，新建默认 light；删除 null/no-preference 两套含糊产品状态。后台管理主题仍是独立 system/light/dark 设置。创建/编辑先提供正确字段与语义，整体排版由后续表单 task 完成。
- 迁移当前配置与需读取的历史/绑定快照到唯一新形状，保留 seed、绑定资产、配置版本及浏览器数据；不可等价映射的旧身份在写入前给出阻塞清单，不随机改写。提供迁移备份、恢复及幂等验证。
- 消费 t081 围栏到实际挂载/运行实例的 manifest、平台和内容完整性结论，再验证过滤后最低字形能力；生成 fontconfig 并完成受控渲染后才发布就绪。必需资产/渲染失败与可选检测覆盖缺失分别报告；健康读取本实例验证结论，不另造完整哈希或资产缓存实现。
- 同步领域模型、OpenAPI/生成类型、运行快照、表单语义、迁移、部署规范与字体门禁；正式栈测试必须穿过容器化 Supervisor 的真实挂载链。

### 非范围

- 不重做表单网格、通用下拉滚动、代理列表查询或环境删除流程；这些交付由同批其他 task 承接。
- 不引入跨机器资产服务、不强制所有网页变暗、不控制管理页面或 Chrome 工具栏主题；不操作用户生产数据或重启现有环境，真实验证使用隔离实例/备份副本。

### 测试策略

- TDD 覆盖部署路径/挂载构造、配置解析、资产清单能力、过滤后空集、损坏/缺失资产、ready 传播；原先锁定 /fonts 误用或英文必禁中文的测试按失效语义整体替换并说明依据。
- 迁移测试覆盖空字体绑定、旧 GPU/配色值、当前与运行绑定不同版本、重复执行、失败前不写入及备份恢复；对不能等价保留的身份要求显式阻塞。
- 真实固定引擎验证两平台 GPU/字体一致性、CJK 开关、light/dark 的媒体查询与网页 CSS；正文、canvas、源端 X11 文字对照，不能用 DOM 文本存在或 CDP 存活冒充渲染通过。
- 运行项目门禁；额外隔离 Compose/Supervisor/Browser E2E 绑定真实字体集，覆盖用户现场故障链；每次只清理本轮拥有的探针资源。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- 固定引擎各平台的 GPU 自动派生、WebGL vendor/renderer 与可用 WebGPU 信息一致性：已由正式 spike `docs/spikes/s026_gpu_platform_capability/report.md` 核实并冻结矩阵（2026-11-18）：SDK 0.6.4 源码证实 GPU 身份由引擎编译内指纹补丁按 `--fingerprint=<seed>` + `--fingerprint-platform=<platform>` 派生，`--fingerprint-gpu-vendor` 是项目自加的原始 flag、SDK 按名合并透传且无任何平台/seed 一致性校验，flag 透传不构成能力证明；平台硬件事实排除 macos×NVIDIA。冻结矩阵：仅 `(windows, 引擎自动派生)` 与 `(macos, 引擎自动派生)` 受支持，手选 vendor 契约取消，旧 `nvidia`/`intel` 值按不可等价映射列入迁移阻塞清单。动态实测部分（两平台多 seed 的 WebGL/WebGPU 实值与重启稳定性）云端无引擎不可执行，与 AC-009 一并登记 p137 本地补验；实测推翻结论时回 s026 修订矩阵。
- 已验证基础事实：当前固定 SDK/引擎中 dark 的两页面媒体查询和深色 CSS 均生效；null 与 no-preference 当前都观察为浅色，但运行身份迁移仍需按实际旧绑定与引擎基线验证，不凭同名认等价。

### 风险与回退

- 风险：配置/快照迁移、GPU 策略及字体暴露变化可能改变持久身份；资产检查可能误把可选检测缺失当硬失败。需先验证备份可恢复，并分别定义完整性、必需字形和可选覆盖。
- 回退：变更前以隔离副本验证配置/DB/字体清单备份恢复；生产未授权不迁移。失败恢复匹配的程序 release 与数据备份，不靠旧字段双读或 Linux 字体回退维持运行，不删除原字体资产。

### 依赖与约束

- 硬依赖 t081（传递依赖 t080）：先交付受管存储、字体目录和实例完整性验证，本 task 在其上完成身份/能力与真实渲染；与 t082/t083、集合查询、删除生命周期及全站呈现共享模型/协议/生命周期文件，冲突经调度字段登记。
- 零兼容分支；目录与技术方案写入 ADR，行为验收以本 task 为准；API 仍是唯一 DB 写者，Supervisor 仍是唯一 Docker socket 持有者。
