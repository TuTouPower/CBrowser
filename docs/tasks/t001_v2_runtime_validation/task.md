# Task spec

## 背景

v2.3 计划要求先验证真实媒体与控制能力，再冻结架构、迁移数据及删除旧链路。当前尚无技术验证证据，旧蓝图仍有单容器与控制租约设计。

## 契约区

### 范围

- 完成 docs/v2_architecture_plan.md 第18章全部17项实验及可重跑验证资产；独立审查结果，记录官方协议差异及实际平台限制。

### 非范围

- 不迁移用户数据，不删除旧运行路径，不发布外部服务，不以源码分析替代端到端媒体测试。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。创建时均为未勾选（`- [ ]`）；实施验证通过后由实施 Agent 就地打勾（`- [x]`）；由 Review Agent 独立复核打勾真实性。技术选型不作为行为 AC。

- [ ] AC-001：两个隔离容器通过同 Profile IPC/X11 传输固定分辨率真实 CloakBrowser 窗口及音频，MIT-SHM 有实际使用证据，不同 Profile 无法访问。
- [ ] AC-002：两个独立页面同时观看并输入同一浏览器，刷新、复制、关闭首个页面不影响其他连接，外部页面关闭不停止浏览器。
- [ ] AC-003：后台页面不降低前台画面帧率，持续视频不错误降帧，全部后台暂停捕获，恢复可见后重建画面。
- [ ] AC-004：真实信令经过 Agent/Gateway 独立隧道，媒体经 UDP mux 正确发布；公网候选可达，TURN 刷新与 relay-to-relay 通过真实网络验证。
- [ ] AC-005：自动化通过 UDS 控制真实浏览器并捕获下载，外部客户端断开后恢复下载捕获；Supervisor/API 重启与正常退出事件不误重启浏览器。
- [ ] AC-006：macOS OrbStack arm64 与 Linux x86_64 均运行实验；结果逐项映射第18章17项，报告区分通过、失败、未运行并保留复现命令。
