# Task spec

## 背景

完整落实 docs/v2_architecture_plan.md 对应正式实施阶段。完成正式拓扑安全与性能输入压力验收；t001全项技术验证通过前不实施。

## 契约区

### 范围

- 正式服务端到端、安全网络矩阵、性能/输入/剪贴板压力工具和可追溯报告，补齐计划19章全部验收；仅修复本轮验收直接发现缺陷，不迁移真实用户数据或删除旧链路。

### 非范围

- 不越过前置验证门禁，不静默缩减计划或改写验收标准；不处理与本阶段无关重构，不覆盖未获具体授权的用户数据或外部环境。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。创建时均为未勾选（`- [ ]`）；实施验证通过后由实施 Agent 就地打勾（`- [x]`）；由 Review Agent 独立复核打勾真实性。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：原生 Linux x86_64 16vCPU/32GiB 无GPU机器运行1/3/10活跃流及10Profile九后台一前台，记录实际CPU/内存/FPS/容量；单活跃流1080p30，LAN RTT≤10ms时输入画面P95≤100ms，就绪后首帧P95≤1秒，过载按规则降低Profile级FPS。
- [ ] AC-002：连续8小时真实媒体/生命周期压力无数据损坏、会话串线和不可恢复退出；保存带时间与环境版本的原始指标和错误，不把短测或容器存活替代8小时验收。
- [ ] AC-003：完成1000次中文组合输入和1000次纯文本剪贴板，覆盖地址栏/普通输入框/受控输入框/富文本与双页面；逐例核对真实结果，保护原剪贴板、权限拒绝提示和后台不覆盖均有实际正负证据。
- [ ] AC-004：正式五服务/双Runtime拓扑逐项通过计划16与19.4安全矩阵，含唯一DockerSocket持有者、API唯一DB写者、Profile卷/网络/IPC隔离、非root/只读/最小权限、CDP无公网暴露、路径逃逸拒绝。
- [ ] AC-005：真实公网/受限网络验证UDP映射、候选、coturn UDP/TCP/TLS和relay-to-relay凭证切换；API/Supervisor/Gateway重启、重复迟到事件、正常退出不误自启及标签页全部19.2行为通过独立黑盒。

### 有意不测

- 无已豁免计划行为；范围外阶段由其独立task执行，不据此取消完整目标验收

### 测试策略

- 正式产物真实部署到独立验收数据根，Chrome真实媒体/输入/网络、8小时原始采样和文件校验；独立review同时复核指标采样方法与全部AC，缺环境保持未通过，不以mock或QEMU容量替代。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- UNVERIFIED-SPIKE：以前置task最终已验证协议/模型/镜像为准；现有原型不得直接视为正式契约。涉及原生Linux/公网/实际数据/外部发布时必须核实入口与授权。

### 风险与回退

- 风险：跨服务权限、并发恢复、凭证或数据一致性可能失败；任何未验证行为不得凭配置字段或模拟通过。
- 回退：隔离worktree、测试数据根和容器资源；保留失败日志，回退本阶段产物。生产数据和外部变更按具体验证备份/回滚方案执行。

### 依赖与约束

- 必须先取得t008完成产物；所有正式实施继承t001全项通过硬门禁。保持计划20实施顺序；公共文档/索引由主控串行收尾。

### Finalization 时更新的 blueprint

- docs/blueprint/testing.md：正式测试入口和测量方法；docs/specs/v2_acceptance.md：平台、容量与安全实证。
