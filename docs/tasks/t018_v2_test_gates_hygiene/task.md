# Task spec

## 背景

2026-11-02 intensive review（docs/reviews/review_20261102_201727）判定测试体系“量大、多数真实，但静默变绿是系统性模式”：E2E 缺镜像变量即整层 skip、前端 E2E 消费过期构建、负断言靠固定 sleep、夹具与生产分叉（重写的 Gateway 替身）、私有内部耦合、资源与端口冲突；CI 引用重组前路径，仓库实际没有门禁；另有归档 spike 无只读说明、仓库卫生缺口。用户以“最好的架构、最少的技术债”为标准全部采纳，并决定 CI 采用三层门禁（A41）与路径隐私守卫（A44）。

## 契约区

### 范围

- E2E 必需模式与构建新鲜度门禁；测试夹具与前置条件统一；Supervisor 测试改用生产 Gateway；时序与断言可信度整改；资源隔离；单元测试架构整改；补齐被放弃的会话 E2E 断言。
- CI 改为现行布局并覆盖全部可移植测试层；本地全量门禁统一入口脚本；删除 release.yml。
- 仓库卫生：路径隐私约定与守卫测试、归档 spike 只读说明与秘密写出路径忽略、行尾规则、vendor 脚本解包安全、spec 中 canary 抽象化、门禁命令去个人路径。

### 非范围

- 不改生产代码行为（为可观测性新增的公开接口除外，须在 note 记录）；生产缺陷修复归 t015/t016/t017；正式部署产物归 t012。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。创建时均为未勾选（`- [ ]`）；实施验证通过后由实施 Agent 就地打勾（`- [x]`）；由 Review Agent 独立复核打勾真实性。技术选型不作为行为 AC。

<!-- /规范 -->

- [x] AC-001：门禁必需模式下，缺任何必需的镜像或缓存变量时测试会话开始即失败并列出缺项；前端 E2E 在构建产物与当前源码内容不一致时拒绝运行并提示重新构建。
- [x] AC-002：测试前置条件由单一模块定义且语义一致；共享 fixture 由 conftest 提供，不存在跨测试模块的 fixture 借用与 sys.path 注入；Supervisor 集成与恢复测试使用生产 Gateway，重写的 Gateway 替身被删除；身份与信令测试驱动生产 adapter；Selkies 私有接口访问集中在每类探针一个适配模块。
- [x] AC-003：测试中不存在“固定 sleep 后断言状态”的模式；状态、状态码与日志断言精确到契约规定值；IPv6 阻断、退避上下限、代次或连接提交、冻结恢复后的帧增长、逐页静音、首帧与输入延迟上限等断言覆盖其声明的行为；清理校验不掩盖原始失败；会话 E2E 关闭页面后断言容器为 running 且实例不变。
- [x] AC-004：端口、显示号、容器与网络名按运行派生或由系统分配，测试状态只写临时目录，证据文件不含会话恢复密钥等敏感值，夹具秘密文件与目录仅属主可访问，测试服务只绑定回环；单次门禁运行不与宿主已有资源冲突。
- [x] AC-005：单元测试只经公开接口断言，负断言以“已处理”确认为前提，时间相关逻辑使用注入时钟，进程全局状态在每个测试后还原，测试 docstring 与实际覆盖一致。
- [x] AC-006：本地全量门禁由单一入口脚本执行（含 E2E 必需模式），testing.md 只引用该脚本（模板契约标记行除外）；GitHub Actions CI 与 release.yml 已移除。
- [x] AC-007：已跟踪的非归档文本文件不含家目录绝对路径（由测试守护），conventions.md 记录该约定；归档 spike 目录有只读说明且 harness 写出的秘密文件被忽略；仓库有行尾规则且存量已规范化；Selkies vendor 解包拒绝穿越条目并校验目录文件集合与清单一致；spec 中不含凭据形态的测试字面量。
