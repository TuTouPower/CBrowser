# Task spec

## 背景

新环境出现在分页列表后，运行条目可能仍缺失。原因是列表配置、全库运行摘要与单环境详情分别更新。新建及复制只刷新列表，启动写入单环境详情，实时事件也只更新已缓存的状态。列表用「已停止」填补资料缺口，掩盖了正在启动、运行或失败的真实状态。当前会话入口、环境切换器、代理引用弹层和全局错误提示同样消费全库摘要。

架构上，服务端应按页面提供完整且可对账的状态读模型。增量事件和初始读取需遵循同一套新旧判定。单补刷新点无法消除请求与事件的到达顺序竞争，也会继续让多个视图分别推导运行状态。一次切换所有现有使用方，废除旧的全库摘要式拼装。

## 契约区

### 范围

- 环境集合由服务端一次返回有界分页和该页每行完整展示所需的运行投影。列表和卡片直接消费同一结果。详情继续按需读取细节，集合只交付行展示与操作所需字段。
- 集合读取、操作结果和实时事件共用单调的新旧判定。覆盖事件早于行读取、慢响应、重连、重复事件和同一配置下实例更替。数据缺失显式呈现未知或加载；状态筛选、总数和分页成员由服务端权威查询收敛。
- 会话入口与环境切换器改用绑定运行状态的集合结果，代理引用随引用数据交付目标状态。全局协调器错误采用紧凑读模型或现有全局事件。当前全局运行总数无界面消费者，随全库运行摘要及其前端缓存与契约一并移除。集合筛选计数继续反映实际匹配结果。

### 非范围

- 启停、恢复、删除和作业服务端状态机的业务规则调整。
- 环境管理页面、会话入口和代理弹层的布局改版。

- [ ] AC-001：在环境列表完成「创建并启动」，或先创建或复制再点击「启动」，状态按服务端进展显示启动、运行或失败，并可实时停止，无需刷新。未取得运行事实时显示未知或加载。有效状态同步到同一环境的行、卡片及操作可用性，预览仅按其真实捕获事件更新。
- [ ] AC-002：分别模拟运行事件早于或晚于集合读取、旧快照晚于新事件、同配置重启换实例、重连丢事件及重复消息，视图最终与服务端一致且已观测状态不倒退。迟到事件不恢复已删除环境。重复或过期事件不引发列表重取。
- [ ] AC-003：状态跨越当前筛选条件时，列表成员、匹配总数和分页均按服务端结果收敛。会话入口准确展示全部运行中的环境，启动中环境不会挤占它们。关闭的切换器不拉取候选状态，打开后显示真实状态。代理引用状态与对应环境一致，全局协调器错误仍能呈现和清除。
- [ ] AC-004：列表每页有上限，获取一页所需配置和运行状态不随环境总量增加请求或查询次数。应用常驻状态读取无需下载所有环境运行条目，列表、会话和代理引用均无每行单独读取运行状态的请求。

- 先将现有复现提升为触达真实列表和事件入口的回归测试。用受控的异步响应顺序测试集合初读、操作结果、重连和事件写入的竞争；用已删除环境与同配置新实例验证生命周期围栏。
- API 集成测试覆盖 20、100、1000 环境下的分页过滤、稳定排序和固定查询数。前端集成覆盖筛选列表、会话入口、已打开切换器、代理引用、全局报错及新旧状态一致性。原摘要专属测试保留为历史或整条移除并注明契约原因，新增测试触达替代路径。

### 风险与回退

- 风险：新投影若只做字段拼接，仍会在快照、事件及页面成员间产生竞态。若移除摘要时遗漏非列表使用方，会丢失会话状态、引用标记或协调器故障提示。
- 回退：本次按一个 API 与前端变更交付，默认不涉及业务数据迁移。需要回退时整体回退成对版本，使用发布门禁复核两端契约。

### 依赖与约束

- 无前置 task。更新 OpenAPI 和生成类型，单环境详情保持现行授权。运行摘要只有一条替代路径，旧摘要在同一交付中移除。
