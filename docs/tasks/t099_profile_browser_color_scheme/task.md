# Task spec

## 背景

选深色后，远程浏览器地址栏、标签栏和工具栏仍为浅色。当前 Profile 配色只传入网页媒体偏好，原生窗口由另一套主题状态决定。现场同一个深色运行配置下，支持深色的页面已变暗，X11 原生窗口顶部仍浅。旧站点页面本身固定白底，网页截图与原生窗口截图均显示白底，视频传输不是该现象的根因。

一个环境的配色应有一个权威选择，并在启动时作用到浏览器原生主题与网页偏好。两层各有明确契约，避免在传输画面中修补亮度。已有 `light` / `dark` 记录直接按同一含义生效，界面说明站点自行决定内容配色。

## 契约区

### 范围

- 将 Profile 的浅色或深色同时应用到真实浏览器原生界面及站点可读取的配色偏好。以绑定配置启动为生效点，复用现有运行配置版本和重启语义。
- 新建和编辑表单使用一致的中英文说明。解释主题作用范围、网页暗色适配边界及配置何时在运行中生效。

### 非范围

- 强制改写站点配色、反色开关、Selkies 编码范围与视频滤镜调整。
- 管理界面主题、支持枚举及 Profile 存储格式调整。

- [ ] [deploy] AC-001：真实有头远程浏览器的标签栏、地址栏、工具栏和原生浏览器菜单随 Profile 配色呈现对应浅色或深色。存量 Profile 在保存另一配色并启动绑定新配置的会话后切换，同一持久化 Profile 从深到浅、从浅到深均通过。不同 Profile 可同时使用不同配色。
- [ ] [deploy] AC-002：真实浏览器中，适配网页收到与 Profile 相同的浅色或深色偏好并采用对应样式。固定白底的对照页仍按其样式显示；管理页面主题切换不改变任一远程浏览器配色。
- [ ] AC-003：新建和编辑表单在中英文均说明浏览器外壳随配色切换，支持适配的网站跟随偏好，配置随新运行生效。选项仍可保存并在重新打开表单时正确回显。

### 有意不测

- 第三方站点视觉结果：使用可控测试页重现暗色适配和显式白底，提高可重复性。

### 测试策略

- Runner 测试覆盖浅色与深色如何从同一绑定配置传给原生界面及网页偏好。真实部署用两种配色、持久化 Profile 双向切换和同时多 Profile 运行证明原生行为，避免只检查参数或只截网页。表单测试覆盖说明、回显与既有重启提示。

- 2026-11-21 在固定 CloakBrowser `146.0.7680.177.3` 与 OrbStack arm64 实测原生主题。启动前将环境配色写入本 Profile 的 Chromium 原生配色偏好，并使用 Chromium 自带主题以消除 GTK 系统主题优先级。真实截图确认存量 Profile 浅 → 深 → 浅、两个 Profile 同时独立配色及固定白底对照均成立。实施后按 AC 验证正式启动路径和 Viewer。

### 风险与回退

- 风险：只设深色可能使回切浅色依赖残留的用户目录设置。引擎开关也可能同时影响页面默认样式，需按站点适配边界验证。
- 回退：回退前后沿用同一存储格式，重新启动环境即可按目标 release 应用配色，保留 Profile 数据。

### 依赖与约束

- 无前置 task。以固定引擎和支持的 Linux/X11 运行镜像为准。单个 `color_scheme` 字段提供唯一配色意图。

### Finalization 时更新的 blueprint

- `docs/blueprint/testing.md`：原生和网页配色的真实引擎验收。
