# Task spec

## 背景

完整门禁中 E2E suite 串行执行，是每轮门禁的主要耗时。`scripts/run_gates.sh` 以单个 `pytest tests/e2e` 进程运行约 40 个 E2E 文件；t032 证据（`.scratch/t032/evidence/junit/e2e.xml`）为 103 个用例、累计 33.5 分钟，其中 `test_frontend_app_e2e`、`test_frontend_session_e2e`、`test_frontend_media_e2e` 三个文件合计约 17 分钟。每个用例起真实 Docker 栈与无头 Chrome，本机 10 核资源在串行下远未用满。t041 一个 task 跑了 6 轮完整门禁，E2E 时长直接决定迭代速度。用户 2026-11-06 批准新建本 task，插在 t036 与 t037 之间，要求只做并行化、不设性能指标、不做 spike。2026-11-06 于 main@0ac2ac6 核实：E2E 用例已部分使用随机前缀与动态端口（`tests/e2e/conftest.py` 等处 `bind(("127.0.0.1", 0))`），依赖中尚无 `pytest-xdist`。

## 契约区

### 范围

- `run_gates.sh` 的 E2E suite 改为多 worker 并行执行。
- 识别并标注时序敏感用例，使其串行执行、不与其它用例并发。
- 消除并行下的共享资源冲突：端口、Docker 网络、容器名、数据目录、basetemp。
- 同一文件内可复用拓扑的用例改为共享栈，用例间只重置状态。
- 保持门禁证据（junit、manifest、`suites.tsv` 退出码）格式与失败归因。
- 在实施笔记记录改造前后全量 E2E 墙钟时间各一次。

### 非范围

- 不修改被测产品代码的行为。
- 不改变 E2E 用例覆盖的行为与断言语义。
- 不并行化 unit、integration、前端 suite。
- 不设性能阈值。

### 风险与回退

- 风险：并行负载加重时序敏感用例的偶发失败；共享栈引入用例间状态泄漏。
- 回退：worker 数降为 1 即恢复串行执行。
