# Task spec

## 背景

当前部署绑定宿主前端产物，空字体卷不能启动 Windows 或 macOS Profile。源码自建和预构建部署均需自动交付两套现有平台字体。

## 契约区

### 范围

- 拆出镜像构建入口，随浏览器镜像交付两套可校验字体，随 Caddy 镜像交付前端。支持从固定下载源或发布者提供的同摘要制品构建，在新实例自动接管字体，并可按镜像清单部署本地或远端镜像。

### 非范围

- 对公网实际发布字体、镜像或安装包。现有引擎官方下载流程和平台指纹契约不变。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。创建时均为未勾选（`- [ ]`）；实施验证通过后由实施 Agent 就地打勾（`- [x]`）；由 Review Agent 独立复核打勾真实性。技术选型不作为行为 AC。review 判 FAIL 且需修改交付内容时，实施 Agent 撤回全部打勾，修复并重验后重新打勾；reviewer 用 `TICK-VALID` / `TICK-VOID` 逐条判定。

<!-- /规范 -->

- [ ] AC-001：干净 checkout 没有宿主字体或前端产物时，构建入口从已配置的锁定源取得字体并生成完整镜像清单，安装入口使用镜像内的前端。摘要错误时拒绝构建。
- [ ] [deploy] AC-002：空卷的隔离部署自动得到两套 verified 字体，分别创建和启动 Windows、macOS Profile 并打开 Viewer；重跑保留已有 Profile 的绑定。
- [ ] AC-003：预构建镜像安装路径按清单取得全部镜像，复用本地镜像部署路径，无需 Dockerfile、前端构建或宿主字体；镜像或字体验证失败不会激活发布。

- 公网实际分发：需要合法可公开访问的字体制品入口和发布权限。使用本地制品与隔离镜像仓测试同一代码路径。

### 测试策略

- 先建立字体导入和清单解析失败用例，验证摘要错误、幂等导入、缺失镜像；再运行项目门禁和隔离部署。

### 风险与回退

- 风险：字体包损坏、导入中断或混用镜像版本。
- 回退：失败保留当前 release，卷内临时目录不参与接管，同一制品可重试。

### 依赖与约束
