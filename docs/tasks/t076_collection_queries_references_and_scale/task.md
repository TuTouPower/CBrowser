# Task spec

## 背景

当前列表通过全量实体加逐环境 runtime 请求拼读，关闭的工作台切换器也为全部环境查询状态。代理仓储每代理重扫运行绑定及版本，10代理/5绑定为72次 SELECT，20代理/10绑定为242次。SSE 更新后又失效列表与单项查询，集合规模增长会继续放大读取。

代理使用计数采用当前配置引用与运行绑定引用并集，前端明细却只按当前 proxy_id 推导，造成显示1个却不可导航、显示多个却漏项。用户要求所有大量环境/代理入口都适配。本 task 以统一、有界、可验证的集合查询契约同时解决正确性与规模问题，不创建单独的空泛性能优化或仅补测试 task。

## 契约区

### 范围

- 在现有持久层实现面向环境/代理列表的集合投影、筛选、稳定排序、总数与有界分页；状态摘要与所需引用信息随集合查询返回，详情按需读取。删除前端先拉全量再逐条查询拼装列表的旧路径。
- 为代理、环境、分组等增长型实体提供按名称检索的有界候选接口及分页契约，保留直连/无分组/全部等语义项；国家筛选使用稳定国家代码，地区候选与总数在后端定义完整范围，供后续交互/呈现 task 使用。
- 统一代理引用关系查询：当前配置引用与运行绑定引用取并集、按环境去重；计数、明细、单项/多项入口、删除保护使用同一语义，关联项可说明 current/bound/both。
- 批量读取 runtime/绑定版本并聚合引用，消除逐代理重扫及逐版本 SELECT；不通过删掉运行绑定引用减少查询。
- 重构共享缓存和 SSE 投影协议，补齐正确更新所需的版本/实例围栏，冷启动与重连取一致快照，增量事件更新对应项；全局摘要由后端聚合，不为隐藏计数或关闭浮层扇出请求。
- 接入环境/代理列表与卡片、工作台入口/切换器、代理使用环境、分组管理等读取入口；定义当前页全选与全部匹配项的语义，批量操作目标按稳定 ID 与明确目标快照确定。
- 将 p119 规模矩阵落实为同一交付的自动化回归：0/1/100/1000条元数据、代理、分组与模拟运行状态；少量真实运行实例验证协议链。记录响应、首屏、搜索、内存/DOM、HTTP 与 SELECT 数，不要求千个沙箱同时运行。

### 非范围

- 不改 GPU/字体或网页配色身份，不重做共享浮层几何/表单排版，不实现停止并删除生命周期；下拉与布局结果由后续 UI task 提供。
- 不引入独立查询数据库或另造事件基础设施；不更改既有网络隔离、账号权限、真实代理节点或生产数据。

### 验收标准

- [x] AC-001：环境与代理列表搜索/筛选针对完整数据集合，排序稳定且分页无重复遗漏；返回范围有上限，页面大小越界不会导致全量返回，总数与筛选口径可解释。
- [x] AC-002：初始列表、工作台入口和关闭的环境切换器不再按每个环境发起 runtime HTTP 请求；列表/卡片与全局状态基于集合状态一致呈现，详情仅在实际消费时读取。
- [x] AC-003：运行状态增量与重连恢复后页面保持正确；旧运行实例或旧配置的迟到事件不能覆盖新实例，重复/重放事件不重复副作用，也不触发无关完整列表重取。
- [x] AC-004：代理使用计数、可访问明细、单项/多项导航及删除保护采用同一引用口径；仅运行绑定占用、当前/绑定同环境去重、两者不同环境及停止解绑均正确。
- [x] AC-005：代理列表固定页面大小下的数据库读取次数不会随代理总数乘运行绑定数增长，运行绑定查询无逐代理/逐版本往返；在10/100/1000数据规模下留存实际计数证明。
- [x] AC-006：增长型候选可通过名称找到末项且不遗漏未加载页，国家→城市范围正确；翻页/筛选后选择范围明确，操作不会落到位置相同但ID不同的实体。
- [x] AC-007：0/1/100/1000条元数据与模拟状态下，环境/代理列表、卡片、入口、关联明细和分组读取完成全量检索与目标定位，无数据截断或遗漏；交互结果可由后续共享组件正常消费。
- [x] [deploy] AC-008：少量真实环境经完整 API/SSE/Browser 链路改变状态和当前代理配置后，列表、使用计数与运行绑定明细一致，重连可恢复，且不改变其他环境身份或数据。（云端不可验，已登记 p126 待 Mac 补验；2026-11-18 用户裁定：云端不可验 AC 视为完成打勾、不阻塞执行链，实际验证留待本地统一补验——本勾为流程处置，非已实测通过）

### 有意不测

- 用户生产环境的实际破坏性操作：不执行；以隔离实例、可恢复副本与真实组件验证，不用生产数据造数。

### 测试策略

- TDD 覆盖分页游标/稳定排序、全局筛选与候选范围、union引用关系、版本/实例围栏、重连及前端冷/热缓存；同一 QueryClient 的请求去重不可被重复统计。
- 真实仓储测试以 SQLAlchemy 执行计数覆盖不同P/R组合、绑定旧版本、无绑定、分页和空结果；计数阶段排除夹具造数。
- 生产组件/真实浏览器配合mock读取生成1000条元数据与模拟状态，自动查找末项、分页、切换布局和选中目标；耗时/请求数原样记录，不靠跳过或提高超时宣称容量通过。
- 运行项目完整门禁及隔离真实栈事件/关联引用验证；p119全站矩阵在本task记录读取与容量部分，后续UI task分别补齐自己的几何/滚动验收，避免重复职责。

### 风险与回退

- 风险：分页引入搜索/计数/批选范围变化，SSE与快照竞争可能回填旧实例，引用聚合可能漏掉bound-only环境；生成协议与前端消费必须同批切换。
- 回退：先在隔离DB和浏览器夹具验证新查询/协议；需要持久化结构变化时提供可恢复备份。回退匹配的程序和数据版本，不保留旧全量+逐条拼读兼容分支，不删除运行引用以绕过问题。

### 依赖与约束

- 无硬依赖；与运行身份task共享模型/生成协议/迁移，与交互/文案task共享列表消费方，按冲突串行实施。
- 既有鉴权、CSRF、幂等与实例围栏必须保持；批量目标不以DOM行号或当前页数组下标作为身份。
