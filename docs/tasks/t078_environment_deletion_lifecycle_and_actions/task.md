# Task spec

## 背景

环境列表操作按canStop在停止与删除之间二选一，运行环境没有删除入口；单项与批量确认用fixed bottom普通div，用户无法及时发现。现有后端delete只接受已停止/无写者的环境，简单补一个红按钮会把合法用户意图直接变成profile_running错误。

本task将列表呈现、确认与后端停止后删除收敛为同一可恢复生命周期。删除必须由服务端保证实例退出、解绑和数据清理顺序，前端关闭不能使流程悬空或扩大目标。

## 契约区

### 范围

- 移除环境管理运行数量统计与最后活跃列；时间数据继续按实际排序/审计契约使用。表格与卡片共用明确操作定义，停止与删除独立，删除入口固定最右并使用danger样式，过渡态有明确可用性说明。
- 单项/批量采用居中可访问模态确认，明确目标、数量和不可撤销影响；运行态使用明确的停止并删除确认，不能偷偷停止环境。
- 复用Coordinator、实例围栏、Profile锁与幂等语义实现后端删除意图：停止写者、确认旧实例退出/解绑、删除数据与引用、报告完成；必要持久化执行阶段以便服务/客户端中断后可查询和恢复。
- 将批量动作定义为明确ID目标集合与逐项结果，停止失败不得删除该项；已确认目标不会因翻页/筛选/排序漂移，成功项与失败项分别处理，失败可重试但不重复清理。
- 错误保留在可见确认/进度交互中，取消前不发删除请求；成功后的焦点回到合理位置。同步API/事件/生成类型、数据清理与恢复验证。

### 非范围

- 不实现reset/clone的新语义，不绕过现有profile数据和运行写者保护，不重做集合查询或通用选择器。
- 本task测试只删除隔离夹具环境，不删除用户生产环境、真实Profile、代理或字体资产；生产发布需另行授权。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。创建时均为未勾选（`- [ ]`）；实施验证通过后由实施 Agent 就地打勾（`- [x]`）；由 Review Agent 独立复核打勾真实性。技术选型不作为行为 AC。review 判 FAIL 且需修改交付内容时，实施 Agent 撤回全部打勾，修复并重验后重新打勾；reviewer 用 `TICK-VALID` / `TICK-VOID` 逐条判定。

<!-- /规范 -->

- [x] AC-001：环境管理不显示运行数量统计和最后活跃列；每个表格行及卡片在运行、停止、过渡与异常状态下都有最右红色删除入口，停止另行呈现且可用性有解释。
- [x] AC-002：点击单项或批量删除仅打开当前视口可见、标题/目标清楚的模态框，不立即删数据；取消或Escape不执行，背景不可误操作且焦点管理正确。
- [x] AC-003：已确认运行态删除由后端停止目标实例，确认退出与解绑后再清理数据；停止失败或存在无法确认的写者时该目标不删除，界面显示可重试的具体失败阶段。
- [x] AC-004：重复确认、网络重试、客户端关闭或服务重启不会产生重复删除或失去已接受的执行结果；旧实例迟到事件不能复活已删除目标或误删新实例。
- [x] AC-005：批量删除严格作用于明确确认的ID集合，成功项移除、失败项保留结果和重试入口；切换分页/筛选后不误删其他行，也不把部分失败报告为全部成功。
- [x] AC-006：已停止环境删除仍遵守完整数据清理语义，相关引用与Artifact处理结果可追踪；单项清理异常不会被静默成功掩盖，其他环境数据和运行实例不受影响。
- [x] [deploy] AC-007：隔离真实运行环境完成停止并删除、停止失败保留数据及中断恢复对照；长列表/低视口/列表卡片下确认与错误始终可见。

#### [deploy] AC 打勾处置注记（契约修订，2026-11-18）

经用户 2026-11-18 明确裁定：「云端把所有 task 能做的全部做完；云端做不了的记录 pending、留待本地统一做；不要在 [deploy] AC 上阻塞，就当它做完了、直接打勾。」据此修订本契约区的打勾语义：对云端环境不可执行的 [deploy] 类 AC（本 task 为 AC-007），打勾表示「云端可做部分已全部完成、按用户裁定视为流程完成」，**不表示已实测通过**。AC-007 的验证内容原文一字不改；其真实环境验证延期至本地统一补验，由 pending p128（`docs/pending/p128_t078_ac007_real_deletion_lifecycle_verification.md`）跟踪，补验时仍须以隔离真实运行环境执行并留证，不得以 mock、skip 或历史结果代替——本注记只变更打勾的流程语义与验证时点，不豁免验证本身。Review Agent 对此类 AC 的 TICK 判定以本注记为准：云端可做部分已完成且补验 pending 已登记者，判 TICK-VALID（处置型）；补验完成并留证后由本地复核闭环。

### 有意不测

- 用户生产环境的实际破坏性操作：不执行；以隔离实例、可恢复副本与真实组件验证，不用生产数据造数。

### 测试策略

- TDD 覆盖生命周期各阶段、Profile锁/幂等、实例围栏、未确认写者、停止/目录/Artifact清理故障和服务中断；注入阶段失败证明不会提前删数据。
- API/仓储集成测试验证操作回执与恢复一致性，客户端真实组件验证确认/取消/批量部分失败/重试，不用真实用户环境造数。
- 真实浏览器测模态焦点、遮罩、长列表/低视口可见性；隔离Docker实例测停止退出后删除顺序及其他环境隔离。
- 运行项目完整门禁并留存删除前后目标ID与阶段证据；旧底栏或仅停止环境可删的测试按新生命周期整体替换、保留原保护行为的等价覆盖。

### 风险与回退

- 风险：删除不可逆、停止与重启竞争可能误删新实例，故障恢复可能重复清理；必须在隔离数据上验证阶段边界、实例身份与幂等性。
- 回退：生产操作仍需另行授权；验证前制作可恢复隔离数据备份。取消尚未接受的删除不改变数据；实现回退前处理完或明确暂停在途删除并恢复匹配DB/程序，不宣称可用代码回滚找回已确认删除的数据。

### 依赖与约束

- 硬依赖集合读模型task的新列表/选择范围与状态消费契约；与身份迁移、表单浮层和全站呈现存在共享文件冲突，串行实施。
- API唯一DB写者与Supervisor唯一Docker持有者边界保持；删除意图不得由页面DOM位置推导。
