# Task spec

## 背景

完整落实v2架构计划第15.4节，从过载的文件/自动化task拆成可独立验收的执行commit。t001全项技术验证通过前不实施。

## 契约区

### 范围

- 从t008原AC-005拆出Profile复制/重置独立交付，写Profile服务/API、Supervisor必要文件复制协调、frontend profiles确认流程及OpenAPI生成类型；不改剪贴板、CDP或媒体协议。

### 非范围

- 不迁移现有用户数据、不删除旧链路、不外部发布，不扩大到相邻模块重构；完整压力、安全与性能门禁不因本task少量用例通过而取消。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。创建时均为未勾选（`- [ ]`）；实施验证通过后由实施 Agent 就地打勾（`- [x]`）；由 Review Agent 独立复核打勾真实性。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：只复制配置会创建新Profile和配置版本，全部有效配置字段保留；不复制浏览器用户数据和Artifact，源Profile不改变。
- [ ] AC-002：同时复制浏览器状态仅在源浏览器停止并确认无写者后执行，复制用户数据且校验文件和配置；运行中拒绝或明确引导停止，不损坏源数据，Artifact仍独立不复制。
- [ ] AC-003：重置按既有指纹种子重新生成语义执行，确认界面明确列出将清数据；不简单删除全部文件并保留旧配置，不影响其他Profile，失败保留源状态或按已验证回滚方案恢复。
- [ ] AC-004：真实前端经API完成配置复制/状态复制/重置，容器重建后Cookie与配置结果符合所选操作；并发源启动或重复请求不会产生半复制目录、重复Profile或跨Profile覆盖。

### 可测试性声明

逐条说明不可自动测试的 AC 及替代验证；全部可测则写“全部 AC 可自动测试”。

全部AC可自动测试；需要真实Docker/Chrome和隔离测试数据，缺失时保持未通过。

### 有意不测

- 第19章1000次输入/剪贴板与8小时基准由t009验收，不豁免这些行为；不访问真实用户私密数据

- 真实停止/运行CloakBrowser、SQLite配置版本和用户数据目录hash、HTTP/ChromeUI、Cookie恢复及并发/故障注入；不mock文件复制来证明状态完整。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- UNVERIFIED-SPIKE：以前置task最终已验证协议/镜像为准；不能将当前技术原型直接当生产契约。

### 风险与回退

- 风险：跨Profile数据污染、并发写者或权限状态失配；日志不得包含私密输入/剪贴板。
- 回退：隔离worktree、测试数据根及专属容器，失败保留证据；涉及删除/覆盖必须先验证备份与可回退步骤，不操作真实用户目录。

### 依赖与约束

- 必须取得t008前置产物，继承t001全项通过硬门禁。t013/t014同改OpenAPI及前端生成类型，不并发写同一批生成资产；调度冲突由task.py登记。
