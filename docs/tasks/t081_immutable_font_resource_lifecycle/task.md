# Task spec

## 背景

运行 API 每次 get_font_runtime 调用同步执行 check_font_set，将 143 个文件、362217650 bytes 重新 SHA-256，最终仅使用按文件名计算的 detection。现场连续两次状态读取产生 286 次哈希、724435300 bytes 读取；约 60 秒采样 rchar 增长 34.6 GB。SSE、字体列表、绑定校验和启动校验还分别复用同一重型 helper。

API 测试固化“每次实时读取、禁止缓存”，Agent 却将同一 set_id 视为不可变并缓存；内容寻址目录同时允许宿主原地修改。根因是不可变资产与可变目录的生命周期未定义。本 task 交付字体发布、验证、审计及元数据消费的一致契约，不用 TTL、mtime 缓存或线程迁移掩盖反复全量读取。

## 契约区

### 范围

- 以 t080 的受管 fonts 卷为唯一正式字体来源；将旧 CBROWSER_FONTS_DIR 限定为显式导入来源，不再由运行请求扫描宿主目录。受信发布者通过受控导入入口写 staging，普通运行容器只读消费精确字体集。
- 保留内容寻址 set_id，发布前完整验证 manifest、文件名安全/唯一性、平台、逐文件摘要与集合身份，原子发布后才将版本标记为可用；重复导入相同内容幂等，不原地修改已发布有效内容。损坏同 ID 的修复必须经受控重新验证与原子替换，不能写一半对消费者可见。
- 在 API 唯一 DB 写者边界内持久化资产目录与验证结论：平台、来源/版本、内容身份、文件数、检测覆盖、验证状态/时间和足以防迟到覆盖的资源修订。文件发布与目录记录使用显式事务/journal 恢复，不能留下 ready 元数据指向未完成内容。
- 导入、首次接管/恢复和显式审计执行完整性读取；runtime GET、SSE、字体列表、默认集选择及普通绑定读取已发布元数据，复杂度与字体字节数无关。必要后台审计有界、按资源去重，并记录审计时间；不宣传每次 GET 可发现任意绕过权限的修改。
- 审计失败撤销资源可用性、阻止新启动并使相关状态显式不可用；同 set_id 的重新验证成功以新资源修订恢复可用。旧失败/成功回执不能覆盖新发布或修复。外部篡改不再构成受支持写入方式，发现后的处理按可验证的审计边界定义。
- 启动消费验证以实际挂入的集合为对象，每运行实例/资源修订验证一次并与 profile_id、runtime_instance_id、config_version、set_id 围栏关联；健康探测和 REST/SSE读取验证结果。必需字形、CJK/locale、GPU 与真实渲染 ready 策略继续由 t075 完成，不在本 task 重复定义。
- 统一 check_font_set 的调用职责，扫描并处置 coordinator、font_sets_router、ProfileService、Supervisor 启动验证、runtime Agent 和指纹验证探针。重型审计不运行于 API 事件循环，设置明确有界并发，停止/取消和错误回执可观测。
- 更新字体列表/状态/错误契约、默认集选择、OpenAPI 与生成类型；删除旧宿主实时扫描和禁止缓存的矛盾路径，补齐导入/修复/审计/恢复指南及相应 ADR。

### 非范围

- 不新增字体下载站、字体删除功能或把平台字体打入镜像/仓库；不改变字体来源要求、Profile seed 或 GPU/CJK/locale 产品选项。
- 不替代 t075 的消费端真实渲染与身份迁移，也不改变 t076 的列表容量与查询协议。

### 验收标准

- [x] AC-001：合法字体集导入后才成为可选择/可启动资源；错误平台、摘要、manifest、集合身份、重复或逃逸文件名均不能被发布为可用。相同内容重复导入返回相同 set_id，不改变既有绑定。
- [x] AC-002：在 staging 写入、校验、发布切换和目录提交之间任意中断，恢复后只能得到完整不可用暂存或完整已发布资产，不出现 ready 指向半成品；恢复及重复导入幂等。
- [x] AC-003：连续 100 次 runtime REST 查询、100 次 SSE 状态组装与 100 次字体列表查询，字体正文打开/读取和完整性哈希调用均为零，结果仍正确呈现绑定、覆盖及最近验证状态。
- [x] AC-004：多个 Profile 共用同一已发布集合时，普通读取不重复校验内容；同实例/资源修订完成启动验证后，重复健康读取不再次哈希，重启或资源修订改变后不会复用错误实例结果。
- [x] AC-005：显式审计能发现删除、额外文件、内容破坏和 manifest 异常，标记资源不可用并阻止新启动；受控修复后状态恢复，旧审计回执不能覆盖修复结果，且不自动删除/重建浏览器用户数据。
- [x] AC-006：运行中的绑定快照与当前待应用配置不一致时，运行状态报告实际实例绑定的字体与验证结论；停止态配置资源信息与运行中观测可区分，旧实例结论不套用到新实例。
- [x] AC-007：慢速或挂起审计期间 API 健康与普通状态查询仍能推进，审计最大并发不超过生产声明上限；同资源重复请求被合并或明确返回在途状态，失败/取消不永久占用执行槽。
- [x] AC-008：字体发布卷对普通消费者不可写，Browser 只能读取绑定集合，Stream 无字体挂载；旧宿主字体目录修改不会隐式改变已发布资源，显式再导入会经过完整验证。
- [x] [deploy] AC-009：在隔离真实容器化 Supervisor 链路导入现场规模或更大合法字体集合，共用绑定实例完成启动验证后持续读取状态 10 分钟，API 不再读取字体正文，实际 Browser 的集合身份与目录记录一致；审计负例与修复正例均留证。
    - 处置注记（2026-11-18）：经用户 2026-11-18 裁定，云端不可执行的 [deploy] AC 打勾表示「云端可做部分已完成、按裁定视为流程完成」，真实验证延期至本地统一补验并由 pending p131 跟踪，不表示已实测通过；AC 验证内容原文不变。

### 有意不测

- 用户生产数据迁移、生产 release 切换与真实账号内容：本次创建授权不包含执行；实施期使用隔离部署、合成状态和可恢复副本。
- 公网、TURN 与原生 Linux x86_64 实机：沿用现有平台验证边界，不能标记为 PASS；不以 OrbStack 结果冒充其他平台结果。

### 测试策略

- 先用生产 helper 包装器记录字体正文打开/读取字节及 SHA-256 次数，以当前 runtime GET/SSE/list 复现红测试；测试使用明显大于小型假字体的集合，不用单纯字符串扫描证明 I/O 已消除。
- 原 test_t053_coordinator_font_runtime.py 中禁止缓存/宿主任意修改下一读立即可见，以及 test_a5_font_scan_offload.py 中每请求审计的旧语义，应整体删除相应失效用例并写明新 ADR，再新增发布/显式审计语义；不得就地把旧预期改成新输出。
- 覆盖并发同内容导入、损坏修复、fsync/rename/DB 提交失败、迟到审计、跨平台同名、绑定旧版本、API 重启目录恢复及无效 metadata；消费者验证必须触达实际挂载。
- 事件循环进度、审计并发上限及重复读取零字体字节为确定性门禁；CPU/rchar 作为现场辅助记录，不使用跨硬件固定 CPU 百分比冒充保证。
- 项目门禁使用 `scripts/run_gates.sh`；真实链路使用 `CBROWSER_RUN_E2E=1 scripts/run_gates.sh`，证据按 `docs/blueprint/testing.md` 脱敏保存，并记录实际镜像 ID。

### 风险与回退

- 风险：把任意可变目录按 set_id 永久缓存会掩盖篡改；目录记录与卷发布失配会误报可用；当前配置与运行绑定混淆会报告错误资产；后台审计迟到可覆盖修复结论。
- 回退：先在隔离副本验证字体卷与目录元数据恢复；失败恢复匹配 DB/资源卷快照和程序 release，保留原导入资产。不以旧目录双读、每 GET 哈希或 Linux 基础字体降级作为兼容通路。

### 依赖与约束

- 硬依赖 t080：只消费其受管字体卷、typed mount 与恢复路径。t075 改为依赖本 task，继续完成必需字形/渲染与产品身份；t083 消费本 task 的只读资产投影。
- 与 t075/t076 共享模型、OpenAPI、coordinator/列表字段及测试，存在并发冲突；API 唯一 DB 写者、Supervisor 唯一 Docker Socket 不变。
- 基础完整性、必需渲染能力、可选字体覆盖是不同状态，不能把 missing_fonts 当完整性错误码，也不能把审计时间解释成当前实际字形证明。
