## Findings

### t035_code_f001 - 只读凭据端点注释不实，且绕过 repository 层直接访问私有 session_maker

- 严重度：minor
- 锚点：`行为缺陷`（文档与实现不一致 + 跨层耦合，当前无坏结果）
- 位置：`src/backend/cbrowser/api/internal_supervisor.py:138-139`（docstring）、`:147`（`session_maker = service._repo._session_maker`）；对照 `src/backend/cbrowser/domain/models.py:222`、`src/backend/cbrowser/adapters/database/repository.py:843-858`
- 问题：`get_proxy_credentials` 的 docstring 写「domain `ConfigVersionSnapshot` projection does not carry the frozen revision」，据此「raw config-version snapshot is read directly」。实际 `ConfigVersionSnapshot` 已有 `proxy_credential_revision: int | None`，`_to_domain_snapshot` 已把快照顶层 revision 映射进 DTO（progress 自述该映射曾 TDD 修复）。端点因此本可直接 `await service.get_config_version(profile_id, version)` 取 frozen revision，却跨层访问 `service._repo._session_maker` 私有属性、自行 import ORM model 读 `ProxyModel` / `ProfileConfigVersionModel`。注释为过时陈述，把 API 层耦合到 repository 私有实现。当前无坏结果：raw 读取同样拿到正确值，端点受 `require_supervisor` bearer 保护，`cfg.proxy_id == proxy_id` 校验防越权读其它代理凭据；实跑 `test_internal_credentials_endpoint_returns_secret_and_frozen_revision` 通过。属文档不实 + 架构耦合，不阻断。
- 建议：改写 docstring；用 `snapshot = await service.get_config_version(profile_id, version)` 取 `snapshot.proxy_credential_revision` 与 `snapshot.config.get("proxy_id")`，去掉对 `_repo._session_maker` 和 ORM model 的直接依赖。

### t035_code_f002 - `delete_profile` 目录清理静默吞错，AC-011「目录都不存在」在异常路径不可观测

- 严重度：minor
- 锚点：`AC-011` / `行为缺陷`（异常路径下删除成功但 Profile 专属目录残留、无告警）
- 位置：`src/backend/cbrowser/services/profile_service.py:353-358`；对照 `src/backend/cbrowser/api/v1/router.py:377-387`（artifact 清理失败有 `except Exception` + `logger.warning`）
- 问题：`delete_profile` 在 DB 行删除后，对 `profiles/{id}`、`runtime/{id}`、`runtime-events/{id}` 三个目录用 `shutil.rmtree(target, ignore_errors=True)`。删除失败（权限、占用、符号链接、只读挂载等）被静默吞掉，无日志、无失败信号，API 仍返回 204。AC-011 要求「删除成功后，DB 行、Artifact 与全部 Profile 专属目录都不存在」；异常路径下该不变量不成立且不可观测，隐私浏览器数据目录可能残留。同一 router 里 `artifact_service.remove_profile` 的失败已显式 `logger.warning`，两处清理口径不一致。正常路径由 `test_delete_profile_removes_private_directories`（`tests/unit/test_t035_profile_domain.py:370-390`）覆盖并通过；异常路径无覆盖。目录清理是 DB 提交后的 best-effort、无法事务回滚，故不求阻断主删除，但失败须可见；按同类 PASS 报告（t034 swallowed-error 类）定 minor。
- 建议：保留 best-effort 不回滚语义，用 `onerror=` 回调 `logger.warning("Profile directory cleanup failed: profile=%s path=%s error_type=%s", ...)`，或先 `exists()` 判断后 `try/except OSError` 告警，使「删除成功」与目录实际不存在一致。
