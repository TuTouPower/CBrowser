# 需求规范：Chrome 外部标签页与会话租约 (chrome_external_tabs)

## 1. 业务目标与适用范围

本文档定义以 Google Chrome 作为唯一官方外部客户端时的双层标签页行为契约与控制租约规范。
彻底杜绝前端绘制虚拟外层标签栏的方案，以 Chrome 原生标签页管理并发浏览器会话。

## 2. 行为契约

### 2.1 双层标签页架构

- **外部原生标签页**：由用户宿主机 Google Chrome 负责管理。
    - `/manage`：Profile 管理、配置编辑、文件归档与审计。
    - `/open`：选择一个已存在的 Profile 并绑定当前 Chrome 标签页。
    - `/browser/{profileId}`：专门承载指定 Profile 远程画面的操控页面。
    - 用户在管理列表点击“打开”时，通过原生超链接 `<a target="_blank">` 在 Chrome 新标签页中打开操控页面。
    - 前端操控页面严格禁止绘制任何外层虚拟标签栏或侧边栏，页面可视区域全部铺满远程浏览器画面。
- **内部浏览器标签页**：由远程容器内运行的 CloakBrowser 真实图形窗口承载。用户直接在远程画面的真实标签栏中新建、关闭或切换标签。

### 2.2 控制会话与排他性租约

- 每个 Profile 同一时刻只能有一个拥有写权限的 `ControlSession`。
- 客户端启动后每 5 秒发送一次心跳：`POST /api/v1/sessions/{id}/heartbeat`。
- 15 秒未接收到有效心跳，租约被标记为断开（`disconnected`），进入 30 秒重连等待窗口。
- 30 秒重连窗口内原标签页重新连接可恢复租约；超时未恢复则正式释放租约。
- 当第二个标签页尝试打开同一 Profile 时，默认拒绝写权限并提示“已有活跃操控会话正在运行”；用户可选择显式“强制接管（Takeover）”，撤销旧租约后签发新租约。
- 关闭外部 Chrome 标签页只会释放该控制租约，不会导致远程浏览器容器被关闭。

## 3. 验收标准

- [ ] AC-001：同时在 Chrome 打开 5 个不同 Profile 的操控标签页，每个标签页独立操作对应远程浏览器，画面互不干扰。
- [ ] AC-002：操控页面中不存在模拟外层切换的虚拟标签栏，所有尺寸自适应铺满容器画面。
- [ ] AC-003：当两个标签页打开同一 Profile 时，第二个标签页被拒绝控制权限并显示接管提示。
- [ ] AC-004：关闭外部 Chrome 标签页后，对应的远程容器进程继续存活运行。
- [ ] AC-005：短暂断网或标签页刷新后，在 30 秒窗口内能自动重新夺回控制租约。
