# 字体集运维指南：导入、接管、审计、修复与恢复（t081）

字体集是发布后不可变的资源（ADR 030）。唯一正式来源是 t080 的 fonts
卷；宿主目录只是导入源。验证结论由 API 持久化在资产目录
（`font_set_assets`），普通读取永不哈希字体正文。

## 导入（发布）

1. 把来源字体放在宿主导入目录（按平台分开），运行
    `scripts/import_font_set.py --platform windows|macos --source <dir> --source-version <版本>`
    （在挂有 fonts 卷的环境执行）。导入会完整验证文件名安全/唯一性、
    平台与逐文件摘要，计算内容寻址 set_id 后原子发布；相同内容重复
    导入幂等，不改动已发布的完好集；同 ID 的损坏集会被受控修复替换。
2. 导入成功只完成「发布」。新集成为可选择/可启动资源还需 API 接管
    （下节）——在接管前绑定该集会被拒绝，这是预期行为。

## 接管（adoption）

- API 每次启动自动接管：枚举卷上已发布集，对没有 verified 目录记录
    的集做一次完整验证并记录。发布与接管之间中断（导入后 API 未启动、
    启动中崩溃）靠接管收敛，不需要人工补录。
- API 已在运行时导入了新集：调用
    `POST /api/v1/font-sets/{platform}/{set_id}/audit` 触发该集的首次
    验证（未记录集的审计即接管），返回 `scheduled` 后等待其完成，再查
    列表确认 `state=verified`。

## 审计

- 对单个集显式审计：同上端点。同集已有审计在途时返回 `in_flight`
    （去重，不重复排队）；全局并发上限 2，审计不阻塞普通状态查询。
- 审计发现删除、额外文件、内容破坏或 manifest 异常时，集被标记
    `failed`：新绑定被拒、新启动被 Supervisor 拒绝；已运行实例不受
    影响，不删除、不重建任何浏览器用户数据。
- 审计时间（`audited_at`）只表示「最近一次完整验证的时刻」，不构成
    当前字形渲染证明；渲染 ready 由 t075 的消费端验证负责。

## 修复

1. 定位损坏集的 set_id 与平台，回到可信来源目录。
2. 重新运行导入（同内容 → 同 set_id，损坏集被原子替换修复）。
3. 触发审计并确认 `state=verified`、`revision` 已递增。修复前的旧
    审计回执即使迟到也会被围栏丢弃，不会把已修复的集重新标坏。

## 恢复

- 目录记录与卷内容不一致（例如恢复了旧 DB 备份）：重启 API，接管会
    对缺记录或非 verified 的集重新验证；记录指向已不存在的集时，对该
    集触发审计会将其标记 failed。
- 整体回退按 release 回退 + DB/资源卷快照成对恢复（见 ADR 030 与
    t080 迁移手册），不要只恢复 DB 不恢复 fonts 卷。
